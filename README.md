# Пепельный престол — Babylon.js starter

Небольшой браузерный прототип: главное меню, коллекция, кампания-заглушка и простой пошаговый бой.

## Запуск
1. Распакуй архив.
2. Открой папку проекта в редакторе кода (например, VS Code).
3. Запусти локальный веб-сервер. В VS Code можно установить расширение **Live Server**, нажать правой кнопкой на `index.html` и выбрать **Open with Live Server**.
4. Игра откроется в браузере.

Не рекомендуется просто открывать `index.html` двойным щелчком: локальный сервер надёжнее загружает ресурсы.

## Что сейчас есть
- интерфейс на русском языке;
- меню, коллекция героев и экран кампании;
- сцена 3D-арены на Babylon.js;
- базовые 3D-фигуры бойцов;
- пошаговый бой: выбор врага, атака, ответный удар, победа/поражение;
- адаптивная вёрстка для узких экранов.

## Что пока не реализовано
Это стартовый прототип, не законченная игра. Нет серверного сохранения, аккаунтов, полноценной прокачки, инвентаря, реальных моделей/анимаций, баланса и полноценной кампании. Сцена использует простые процедурные фигуры.

## Структура
- `index.html` — разметка приложения и подключение Babylon.js CDN.
- `styles.css` — стили интерфейса.
- `game.js` — данные героев, экраны и простая логика боя.

## Публикация
Для публикации на хостинге статических сайтов достаточно загрузить эти три файла. Для GitHub Pages можно создать репозиторий, загрузить файлы и включить Pages в Settings → Pages.

## Мобильная прокрутка
В CSS для canvas используется `touch-action: pan-y`, чтобы вертикальные свайпы могли прокручивать страницу на телефонах. Если в itch.io используется встроенный режим fullscreen/embedded, проверь страницу и в обычном браузерном режиме.


## TECH-001 — стабилизация (5 ноября 2026)

Исправлены сброс боя при входе на арену, единый обработчик атаки/повтора,
автоматический выбор следующего живого врага, отклонение выбора побеждённого
противника, состояние кнопки и текста после победы/поражения. Дополнительный
`BABYLON.GridMaterial` заменён на встроенный `BABYLON.StandardMaterial`
с сетчатым отображением, чтобы не требовалась отдельная библиотека материалов.
Рендеринг сцены пропускается, если экран боя не активен.

Проверено: `node --check game.js` и модельные автоматические тесты логики.
**Не проверено:** фактическая WebGL-отрисовка в браузере, работа на смартфоне,
замеры FPS, памяти и GPU. Для визуального теста требуется доступ к Babylon.js CDN.

При каждом входе через главную кнопку, кампанию или карточку «Арена» начинается
новый демонстрационный бой. Это временное правило стартера, а не правило
будущей сюжетной кампании.


## TECH-002 — мобильный интерфейс (5 ноября 2026)

- Добавлена подсказка при портретной ориентации телефонов и планшетов шириной до 1100 CSS-пикселей. Браузерная блокировка ориентации не применяется.
- В невысоком горизонтальном окне арена располагается рядом с боевыми контролами, чтобы сократить вертикальную прокрутку.
- Сохранён обычный вертикальный скролл страниц; управление камерой Babylon.js по canvas не прокручивает страницу.
- Учтены безопасные поля экрана (`viewport-fit=cover`, `safe-area-inset-*`) и минимальные сенсорные размеры кнопок.
- Боевая логика и игровой контент не менялись.

Проверка в эмуляторе не заменяет проверку на реальных смартфонах: после публикации проверьте portrait/landscape, касания камеры, доступность кнопки и прокрутку коллекции.


## TECH-002.1 — небольшой hotfix интерфейса (05.11.2026)

На небольших экранах в горизонтальной ориентации высота боевой арены и панели бойцов уменьшена для сохранения видимости футера. На высоте до 390 CSS-px также сокращены вертикальные отступы. Исправление затрагивает только `styles.css`; игровая логика, HTML и Babylon.js не изменены. Рекомендуется проверить iPhone Safari после публикации, особенно футер и доступность кнопки атаки.

## TECH-003 — жизненный цикл Babylon.js (05.11.2026)

- Engine, Scene и демонстрационные meshes создаются только при первом входе в бой; при повторных входах переиспользуются.
- Цикл `runRenderLoop` включается только на экране боя, останавливается на остальных экранах и при скрытии вкладки (`visibilitychange`).
- Используется один и тот же callback отрисовки; повторные входы не создают параллельные циклы.
- Слушатель `resize` создаётся один раз и меняет размер engine только на видимом экране боя; после возвращения на арену размер обновляется.
- `preserveDrawingBuffer` убран: чтение кадра не используется, а постоянное сохранение буфера не требуется.
- Во время переходов сцена остаётся в памяти намеренно: переиспользование дешевле повторного создания для небольшого прототипа. При внедрении множества арен потребуется явный lifecycle/dispose.

Проверено: синтаксис JS и автоматический тест переходов/visibility с подставными объектами Babylon.js. Не проверено: реальные GPU/CPU/FPS/память на смартфоне — это отдельная приёмка на опубликованной версии.

## TECH-004A — изоляция демонстрационных боевых правил (05.11.2026)

- Новый `combat-core.js` содержит состояние демонстрационного боя, проверку выбранной цели и простые правила урона/ответного удара. **Не** импортирует DOM или Babylon.js.
- `game.js` оставлен ответственным за интерфейс и синхронизацию с визуальной сценой; вызывает `CombatCore`.
- `index.html` загружает `combat-core.js` перед `game.js`. Для GitHub Pages сборка не требуется.
- Упрощённые действия, HP и атака демонстрационных персонажей **не изменены**.
- Полная система скорости, выбора активного героя и способностей **не внедрялась**: параметры TBD согласно `docs/Combat_Specification_1.0.md`.

Проверены синтаксис и автономные тесты логики: выбор цели, её гибель и переключение, победа, поражение, повторная инициализация, порядок подключения скриптов. Это **не** доказательство браузерной работоспособности после разделения файлов: требуется регрессия в Safari после публикации.
