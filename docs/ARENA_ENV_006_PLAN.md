# ARENA-ENV-006 — экспериментальная 3D-арена (вариант Б из ARENA_ENV_005_PLAN)

**Статус:** ЭКСПЕРИМЕНТ — [В РАЗРАБОТКЕ], draft PR, **не сливать**. Включается только флагом `?environment=env3d`; по умолчанию остаётся 2D-фон ENV-005. Версия ветки `v0.3.213 · ARENAENV006`.
**База:** `main` be55800 (v0.3.212 · ARENAENV005). **Арт:** `assets/arena-env005-terrace.webp` (картинка к задаче не приложена).

## 1. Что изучено и почему 3D-фон раньше не получался

| Источник | Вывод для ENV-006 |
|---|---|
| ENV011/ENV012B (PR #178–#181, закрыты) | Процедурная подгонка рельефа: технически проходит, художественно провал (навес, плоские массы). ENV013: сначала композиция по реальному кадру, потом 3D; «без циклов» |
| ENV017 (`combat-environment-017.js`, «коричневый пирог») | Только вершинные цвета, ни одной текстуры; камера `alpha=-3π/4` — **старая**, после ARENA-VIS-001 сцена смотрит мимо неё. Масса без материала не может выглядеть как арт |
| ENV010 GLB-пайплайн | Отдельная модель окружения = недели художественной работы без гарантии совпадения со стилем |
| ENV022 → ENV-005 | Арт владельца за прозрачным WebGL выглядит хорошо, но не имеет перспективы: при pinch-zoom бойцы уменьшаются, а плиты под ними — нет |
| `game.js` initBabylon | Сцена одна на все бои (`initBabylon` раз), `alpha:ENV022_CONCEPT_PREVIEW`, CV007 в режиме `conceptBackdrop` декораций не создаёт; выход из боя — `showScreen(id!=="battle")` |
| ArenaStageView / ArenaVis001 | Камера `alpha≈131,0°`, `beta 1,12`, `fov 0,85`, `radius 7,6` (6,6–10,5), цель `y=1`; бойцы на `y=0`, blob-тени `y=0,025`; ACES, контраст 1,15, экспозиция 1,25 |

**Главная причина прошлых неудач:** 3D пытались *нарисовать кодом*. Арт уже есть и утверждён — надо не рисовать заново, а дать ему глубину.

## 2. Варианты

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| (а) гибрид: 3D-пол и балюстрада + 2D-задник | Пол с тайловым материалом, задник — плоскость с артом | Настоящий пол | Шов пол/задник, свой материал пола не совпадёт с картиной; повтор ENV011 по риску |
| (б) низкополигональная сцена с текстурами из арта | Собрать террасу, арку, дерево мешами, вырезать текстуры | Полное 3D | Объём работы и та же история «пирога»: стиль решает арт, а не меши |
| (в) GLB (Meshy/Blender) | Модель окружения | Можно вращать камеру | Meshy — вход владельца; стиль не совпадёт с картиной; бюджет 1,5 МБ тесен |
| **(г) проекция арта на прокси глубины (выбран)** | Картина проецируется из утверждённой камеры на лёгкую 3D-геометрию: пол `y=0`, стоячие «стенки» (балюстрада, арка, дерево) на линии касания пола, дальний слой ущелья/неба | В исходном кадре = ENV-005 пиксель в пиксель; при zoom — настоящая перспектива; 1 меш, 1 материал, 1 текстура | Работает для «камера движется только по лучу» (наш случай — вращение заблокировано). Края за пределами картины при максимальном отдалении — синтезированы |

Вариант (г) — это вариант (а), доведённый до конца: и пол, и задник берут пиксели из одной картины, поэтому шва и спора стилей нет.

## 3. Как устроено (`combat-environment-006.js`)

- **Проектор** — та же математика, что у Babylon (`ArcRotateCamera`, `LookAtLH`, `PerspectiveFovLH`), плюс правило CSS `cover`/низ из ENV-005 на экране 844×390. Node-тест проверяет: каждая вершина несёт тот тексель, который видит эталонная камера (ошибка < 1e-6).
- **Прокси глубины** — по таблице `EDGE` (линия, где стоячие объекты касаются плит, и где начинается дальний план). Каждая колонка — «срез проектора»: дальний слой (глубина 60) → нулевая «юбка» → стенка на глубине точки касания → пол `y=0`. Сетка 77 × 63 вершины, 9 424 треугольника, без разрывов.
- **Текстура** `assets/arena-env006-terrace-projection.webp` 2048×1024, **155 КБ**: середина — картина ENV-005 в родных пикселях (верхние 120 строк никогда не видны и отброшены), поля по бокам и снизу — зеркальная копия, размытая и притемнённая, хранится с низкой плотностью. Тень под HUD из CSS ENV-005 запечена. Скрипт: `tools/build-arena-env006-texture.py` (Pillow + numpy, только инструмент).
- **Материал** — без освещения, без тумана, со своим `ImageProcessingConfiguration` без ACES: фон держит цвета арта, бойцы — свет VIS-001. Меш `isPickable=false`, `freezeWorldMatrix`, `alwaysSelectAsActiveMesh`.
- **Жизненный цикл** — создаётся при входе в бой (`ensureArenaEnv006` после `initBabylon`), удаляется при выходе (`showScreen` ≠ battle) и при ошибке старта. Пока текстура грузится, меш скрыт и виден CSS-арт ENV-005 (он же — запасной вариант при ошибке).
- **game.js** — +15 строк; `index.html` — один `<script>`. env017/env010 и режим по умолчанию не тронуты.

## 4. Бюджет iPhone — замеры (Chromium + SwiftShader, 844×390, DPR 1)

| Цель | Факт |
|---|---|
| Загрузка ≤ 1,5 МБ | **166 КБ**: текстура 154 896 Б + модуль 11 372 Б. CSS-арт ENV-005 (145 КБ) грузится и в 3D-режиме как подложка |
| Текстуры ≤ 2048 | 1 × 2048×1024 (видеопамять ≈ 8 МБ + мипы ≈ 11 МБ) |
| ≤ 30 draw calls | **1** (весь бой: 18 → 17 без окружения) |
| ≤ 30 тыс. треугольников | **9 424** (замер `getActiveIndices` с окружением и без) |
| Без shadow map и постобработки | Да: тени — blob VIS-001; новых проходов нет |
| Dispose без утечек | Бой: 149 мешей / 44 материала / 24 текстуры → вне боя 148/43/23 (ENV006 = 0) → повторный вход 149/44/24 |
| Совпадение с 2D | Средняя разница кадра с артом **2,6–4,5 из 255** (позы бойцов, пересэмплирование) |

**Не проверено:** физический iPhone (FPS, нагрев, время декодирования 2048×1024 при каждом входе в бой), WebKit — только в CI.

## 5. Находка по ENV-005 (не исправлялась)

Текущий 2D-фон на ~**+9/+11/+17** (R/G/B) светлее и голубее арта: прозрачный WebGL очищается цветом `(0,035; 0,045; 0,065)` с альфой 0, и при премультиплицированном смешивании этот цвет **прибавляется** к CSS-картинке. ## 8. Риски и честная оценка

- **Выигрыш:** при pinch-zoom арена ведёт себя как настоящая — пол масштабируется с бойцами, балюстрада и ущелье остаются вдали (см. кадры «дальний zoom»: в 2D плиты остаются огромными при уменьшившихся бойцах). В исходном кадре разницы с 2D нет.
- **Ограничения:** камера только приближается/отдаляется по лучу; вращение или наезд в сторону сразу покажут «картонность» стоячих срезов. Цветы и камни в нижних углах лежат на полу (не стоят), при отдалении слегка растягиваются. При максимальном отдалении по краям видна синтезированная размытая рамка (зеркало картины) — читается как виньетка.
- **Цена:** +155 КБ загрузки и ≈ 11 МБ видеопамяти против ≈ 6 МБ декодированной CSS-картинки; один лишний draw call; декодирование текстуры при каждом входе в бой (требование dispose).
- **Стоит ли того:** как замена 2D по умолчанию — **пока нет**: игрок видит разницу только при pinch-zoom, а это вторичное действие. Как основа на будущее — **да**, если появятся вещи, которым нужен настоящий пол: тени/следы ударов на плитах, разные локации из одного арта (тот же скрипт на новую картину), лёгкий «вздох» камеры на мощных способностях. Рекомендация: держать за флагом, проверить на iPhone, решение — по итогам.
