## API и реализация
- `CombatCore.createBattle(heroes,waves,{combat2:true,...existingOptions})` — нативный opt-in. Без него прежний режим; входной флаг героя не включает режим. Нет localStorage, второго ядра, eval/строковых патчей в runtime, изменения наград или UI.
- ability-data.js: выбранный kit накладывается на SkillCore только для снимка ally в экспериментальном бою. Сава: B +50–75 meter без тега, S +250–300 cap950 с накопленным boost, P .8–.9× own + .5–.6× helper с cap own ATK до crit. Art S guard/recover, passive reaction; старые fieldNote не описывают новую ветку. Art/Sava leader definition null в режиме (слот построения остаётся допустимым без ауры, UI/eligibility вне боя ещё не изменены). Ren/Nada/Liora исходные навыки, shared mark bonus12 как в B14.6.
- combat-core.js: один native executor, `performActorAbility(battle,id,targetIndex,helperIndex)` и `performPlayerAbility(battle,id,helperIndex)` (дополнительный аргумент; прежние сигнатурные якоря оставлены для старых исследовательских тестов). Helper должен быть другим живым союзником, проверяется до мутации, резерв RNG на два удара; вторичный hit не тратит его ход, CD, weakening, не запускает новый skill/passive chain, не выбирает новую цель. При полезном assist одно значение boost; смерть/волна очищают boost. `previewSignal(battle,actor,amount,target)` — read-only forecast; cap сохраняет готовый meter, нулевая выгода отклоняется.
- Art восстанавливает Protection .65× ATK до max и не менее одного guard; реакция при разрешении подготовленного удара снижает damage до guard, расход ceil(block/2) Protection (именно тестированный B14.6, НЕ новый 1:1 вариант B15); один раз между ходами Art.
- NPC ridge-slinger/trail-interceptor: подготовка занимает собственный ход, сохраняется ID цели, на следующем ходу P либо обычная атака при срыве/утрате цели. Taunt меняет фактическую цель. События combat2-threat-prepared/resolved/cancelled, combat2-cover, combat2-protection, combat2-meter; assist damage содержит rootId, parentId, sourceId, depth=1, raw. Убитый источник больше не хранит prepared; смерть намеченной цели отменяется на ходе источника. Сохранён stable CTB; enemy-decision только в opt-in применяет tested ID tie-break выбора цели при одинаковом HP.
- auto-decision.js: port tested policy для всех пяти героев, включая deadline Art/Nada, group/taunt Liora, Sava explicit helper и signal; priority guard. План read-only, исполнитель тот же, что ручной.
- Никаких изменений в game.js, index.html, CSS, моделях, прогрессии, live NPC stats, сохранениях, GDD/каноне или версии. Существующие лаборатории оставлены для сравнения. Native API пока только в тестах, новая публичная арена отсутствует.

## Проверки, исполненные в V8
Точные fetched main source и изменённые branch source собраны в V8 для теста, runtime — статические JS-функции. Не сравнивались текстовые сообщения и формат событий целиком; имена native и lab отличаются намеренно. Тест считает наблюдаемые события: подготовка109, отмена38, разрешение38, реакция30, восстановление Protection36, meter119, assist damage53; это события, доступные после команд, не полная независимая статистика всех действий. 8 прямых групп контрактов: default legacy replay равен baseline, исключение лидеров, атомарный отказ плохого helper, cap/root/no helper turn, signal/preview/boost, Art cover, primary kill/wave cleanup, native auto execution. Отдельная проверка старого режима в этом тесте — один детерминированный сценарий, не весь регресс.

## Самокритика / открытые задачи
Нативный opt-in не меняет существующий UX. Нельзя считать CI или совпадение 48 пар авторской приёмкой. Нет новой 3D сцены, новых реальных миссий, фактической проверки iPhone или художественной оценки; synthetic pressure/gear fixtures остаются только в тесте. Ren P оставлен как live single-target в изолированном кандидате; исходные REN/CHAR документы по противоречию не найдены, решения владельца о спорном эффекте нет. Boss immunity, фактический NPC scaling, full campaign/reward/reload, неравная прокачка и пользовательская понятность остаются B17.3/4. Assist secondary damage не перерассылается в пассивные триггеры, поэтому до интеграции режимов с особым подсчётом KO (NetworkScoreCore) отдельно проверить scoring contract; сейчас новый режим не вызывается ни одним reward-bearing route. Старые исследовательские адаптеры используют string anchors; сохранены ключевые якоря, совместимость полного набора требует CI. Полный Node и профильный браузерный регресс нужны до публичного включения, selective CI PR pending.
