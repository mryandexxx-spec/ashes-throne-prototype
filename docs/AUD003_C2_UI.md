# AUD003-C2/UI — художественная переработка
26.11.2026 · [В РАЗРАБОТКЕ]. Владелец отверг техническое оформление #562. Теперь лаборатории должны иметь игровую визуальную подачу с первого осмысленного прототипа. Не считать зелёный CI художественной приёмкой.
## Решение
Сценическая оболочка штаба, крупное досье Арта, центральная иллюстрированная карточка задания, справа цепочка дел и альтернативных планов. В бою отдельная 2D художественная арена, портреты и существующие утверждённые иконки навыков, чёткая цель, выделение действующего героя и выбранной цели, реальная обратная связь, отдельный результат. Состояния закрытых задач доступны для просмотра, но не запуска. Один экран без глобального скролла, список дел скроллируется отдельно; responsive landscape/portrait. Сброс подтверждается. Вся механика #562 сохранена; добавлены только read-only поля боевого view. Не вводить вторую систему боя и 3D в меню. Боевой экран — 2D, не полноценная Babylon-арена; иллюстрации существующих сцен используются как настроение, не утверждённый сюжет. 
## Проверки и ограничения
Скилы game-ui-ux и game-feel, UI_DESIGN_SYSTEM / UI_MIGRATION_PLAN. Существующие ассеты, без новых внешних ресурсов. Проверить Chromium/WebKit 844×390, 932×430, 844×320, 390×844: размеры, ошибки и 404, закрытый план, отказ/результат/сброс; полный путь I→III и делегирование на 844×390. Снимки сохраняются workflow. Художественная приёмка только после осмотра реальных рендеров; физический iPhone и Pages отдельно. Тестовые статы, нет реальных наград, постоянных сейвов, техник II/III и нового канона.
