## Предлагаемый контракт главы I
- Один бой First Play и один новый реальный M1; не добавлять бой ради количества. Существующий main-cam-001-m1 ID, proof, receipt и отдельный режим сохранить. Пролог не считать повторяемой миссией главы. Не менять боевой тип пролога; M1 стандартная победа над противниками, текущие два NPC только кандидаты по балансу. 
- Начало M1: краткий бриф/понятная цель и опциональный кадр, затем обычный экран состава. Победа: явно видимый сюжетный результат, короткий опциональный кадр/предмет, экран наград; после receipt следующий путь открыт, а фактическое завершение действия не зависит от выплаты. После проигрыша/отступления не показывать успех/сюжетное открытие; retry без принудительного просмотра. Полный skip First Play даёт нейтральный бриф M1 без утверждения спасения, не создаёт FP reward. Skip только сцен не отменяет фактических побед. 
- Карта: компактная 2D, отдельная визуальная стадия завершённой главы, не делать заглушку кликабельной. Показать только близкий следующий маршрут, независимый заменяемый SVG, без утверждения географических деталей. Звёзды не блокируют сюжет. Replay не меняет факты и не дублирует награды. 
- Цели по темпу (не измерены): первое действие до 30с без загрузки, M1 подводка 5–8с и финал 5–10с, доступный skip, 70% активной игры как цель; без диалогового движка, обязательных дополнительных выборов и новых боевых правил. 
## CAM-ROSTER — следующий этап, до производства новых миссий
1. Сверить HeroCollectionCore.START, IDS, valid, owned, grant, MISSION_UNLOCKS, StarCore, ProgressV3Core (создание, валидатор, runtime, сериализация), ProgressWriterCore, RewardPolicyCore, save-core, начальные данные/выбор состава, все места проверки владения, hero sources, награды и все режимы. Сейчас valid требует >=5; owned ограничено START; нельзя просто заменить START на 2 — это сделает будущих героев недоступными. Разделить набор доступных в игре героев и стартовый набор; rank/ownership — единый источник истины, locked видимы в коллекции без выбора в отряд. 
2. Чистый старт ровно Ren/Art, действительный отряд 1–2 из имеющихся, никакого доступа к закрытым через учебную, OPS, хронику или сеть. При обязательном составе хроники использовать предусмотренный GDD временный сюжетный экземпляр, не постоянную выдачу; исследовать текущую реализацию и не сломать существующий режим. Не менять канон из-за боевых данных. Не обещать поддержку старых тестовых профилей ценой сложности: владелец разрешил отказаться от обратной совместимости, но обработка ошибки/сброс только игровой namespace обязательны.
3. Проект выдачи: гарантированный герой при подтверждённой первой победе общего сюжетного узла (не альтернативного пути), с выполнением необходимых сюжетных условий. Не привязывать к 3 звёздам, случайным осколкам, skip, отдельному режиму. Точный ID, hero rank/level и награды только после согласования и аудита экономики; не создавать «фантомную» победу или выдачу заранее. Существующая receipt-дисциплина: под эксклюзивным writer проверить durable proof, единственная транзакция выдачи и receipt, reload/повтор не дублируют. Если формат не поддерживает grant вместе с receipt, отдельный ограниченный контракт с проверкой атомарности, не два независимых изменения сейва. Герой после получения доступен в коллекции/отряде, прогресс сохранён. Превью ближайшего получения — без спойлера. 
4. Баланс M1: реальная команда Ren/Art L1 (skip), Ren L2/Art L1 (после FP и апгрейда за 39), добровольный повтор. Проверить текущий NPC guard/interceptor L1; тестовые 40 кромов и <=10 действий третьей звезды не считаются утверждённым балансом. Использовать текущие навыки Рена и Арта (ослабление, страховка, disruption), без обязательного лекаря, скрытых усилений или принудительного фарма. При необходимости менять только параметры экземпляров миссии, не глобальные формулы и не весь каталог NPC. Ручная победа осмысленной тактикой, по возможности разные допустимые стратегии, осмысленное поражение с плохими решениями, достижимая третья звезда либо честная поздняя цель. Модельные тесты + ручной UI сценарий; auto отдельно. 
5. Тесты: чистый старт, владение 2/3/4/5 и выбор 1–N, скрытые/locked, rank/level, подмена ID, loss/retry/retreat/skip, сохранение до/после claim, две вкладки/exclusive, невалидный сейв, reload/replay, двойной claim, неизменность других режимов, обязательные герои хроники/временные актеры, отсутствие доступа к невыданным героям через источники. Full Node + selective + First Play/M1/mobile squad Chromium/WebKit. Проверить 844×320/844×390/932×430, safe-area, pre-tap bounds и hit target. Физический iPhone отдельно.
