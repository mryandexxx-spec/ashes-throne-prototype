# CI-SELECTIVE-001 — аудит и политика проверок

**[РЕАЛИЗОВАНО в main, PR #438]** 21.11.2026. Подтверждено одним автоматическим PR workflow; отдельные задания прошли проверку, полный Node 923/923 успешен.

## Исходная проблема
- На main существовали **54** отдельных workflow в \`.github/workflows\`; при изменении \`game.js\` PR #437 запустил **46** workflow, нередко повторно \`npm test\`.
- Много проверок привязано к общим \`game.js\`, \`index.html\`, \`styles.css\` и \`package.json\`, хотя тестируют отдельные старые фичи.
- Регрессии становились трудны для диагностики: одна устаревшая Node-заглушка создавала несколько одинаковых красных CI, а тяжёлые WebGL-сценарии многократно запускали GLB.

## Новая структура
- **Один обязательный автоматический workflow**: \`.github/workflows/ci-selective.yml\` на PR в \`main\`, с \`concurrency.cancel-in-progress\` для устаревших запусков.
- Быстрый Node job вычисляет изменения через merge-base PR, делает \`node --check\` изменённых JS, проверяет соответствие версии \`package.json\` и футера \`index.html\`, выбирает лишь относящиеся к изменению Node-тесты.
- Условные мобильные browser jobs (Chromium + WebKit): **squad**, **battle**, **lore**, **network**, **hero**. Запускается только нужный профиль, на основании затронутых путей.
- Общие \`game.js\`, \`index.html\`, \`styles.css\` запускают базовый squad/WebGL smoke. Изменения конкретной подсистемы дополнительно запускают её профиль.
- Изменения только документации и workflow не запускают 3D/browser; сам CI-сценарий проходит синтаксическую проверку.
- Все прежние 54 workflow **сохранены и переведены на \`workflow_dispatch\`**: их можно вручную запустить из вкладки Actions при рискованных правках, перед релизом или после диагностики. Их тестовые скрипты не удалены.
- Отдельная кнопка \`CI / full Node regression (manual)\` запускает полный \`npm test\`, только по запросу.

## Что проверяет профиль squad
\`tests/squad-001.test.js\`, \`tests/combat-014b-leader-squad.test.js\`, \`tests/ui-hero-002-squad.test.js\`, \`tests/squad-recover-3d.test.js\` и реальный \`tests/squad-recover-browser.cjs\` на мобильных размерах, с 5 GLB, экранной проекцией, возвращением героев в ростер, лидером и восстановлением экрана.

- **Исключение при изменении самого CI:** один дополнительный job с полным `npm test` (только когда затронуты `.github/workflows/` или скрипт селектора). Обычный UI PR без CI-файлов продолжает запускать лишь узкий smoke.

## Риски и границы
- **Снижение автоматического охвата — сознательное решение.** Ошибка в не затронутой подсистеме может не обнаружиться до ручного полного прогона. Особенно \`game.js\` — общий монолит; он получает базовый smoke, но не все сценарии разом.
- Перед сложным изменением боевой логики, кошелька, сюжетного сохранения или выпуском стабильной версии вручную запускать \`CI / full Node regression\` и профильные исторические браузерные workflow.
- Если в GitHub Rulesets/Branch Protection указаны старые обязательные check names, заменить их на \`CI / selective smoke / Diff-aware Node smoke\` — иначе merge будет ждать отключённые проверки.
- Оставлены без изменений процедуры публикации GitHub Pages; merge в \`main\` сам по себе не доказывает публикацию.
- Автоматическая эмуляция WebKit **не эквивалентна** проверке на физическом iPhone Safari.

**FIRSTSESSIONP0B:** изменение `first-play-core.js` (контракт checkpoint) также запускает полный Node audit, как остальные изменения ядра сохранений. Обычные изменения иллюстраций/CSS/сценария не получают этот дополнительный audit.
