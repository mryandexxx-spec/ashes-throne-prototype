# Combat-008C-TAP — кнопки после поворота Safari

**Статус:** [В РАЗРАБОТКЕ], необходимо проверить на iPhone Safari.
**Сборка:** `v0.3.7 · CBA008C-TAP`.

## Симптом
После слияния PR #51 владелец сообщил, что при повороте во время боя landscape → portrait → landscape перестают реагировать кнопки. Сцена при этом отображается. Фактическая причина не измерена на устройстве; вероятный источник — полноэкранный портретный overlay с `z-index:9999`, который после возврата может продолжать перехватывать касания. Дополнительный риск — `touch-action:none` у `body.battle-mode`.

## Исправление
- Портретная подсказка теперь **не перехватывает касания никогда**, поскольку она информационная, без элементов управления (`pointer-events:none!important`).
- При пересчёте размеров после смены ориентации подсказка явным образом скрывается в landscape через `hidden`, даже если Safari временно оставляет старую медиастилизацию. В portrait остаётся видимой.
- Удалён глобальный `touch-action:none` у `body.battle-mode`, но он сохранён для самого 3D-Canvas. Боевые кнопки имеют собственный `pointer-events:auto` и `touch-action:manipulation`.
- Расстановка 3+2, изометрия и существующий предел приближения (`radius=12`) не меняются. Правила боя и сохранения не затронуты.

## Проверки
- `npm test`: регрессии плюс headless-сценарий portrait → landscape, скрытие overlay, вызов обработчиков кнопок скорости и способностей, выбор цели по 3D-мешу после поворота.
- Обязательно проверить на физическом iPhone Safari после GitHub Pages: сверить `v0.3.7 · CBA008C-TAP`; провести бой, повернуть устройство в portrait и обратно, проверить **выход, базовую, особую, атаку, автобой, скорость, список бойцов, журнал и выбор 3D-цели**. Повторить два-три раза; проверить смену волны и возврат из фона Safari.
- Автоматические тесты подтверждают обработчики в имитации DOM, но не аппаратные сенсорные события Safari. Мобильная приёмка обязательна.
