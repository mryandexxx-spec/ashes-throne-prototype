# Combat-011 — цели и эффекты

**Статус:** [В РАЗРАБОТКЕ]. Общая направленность этапа утверждена владельцем; конкретные новые способности и их баланс — **не утверждены**.

## Combat-011A: безопасный первый инкремент

Цель: выделить независимую от UI и Babylon.js логику **предварительного определения целей**, сохраняя текущий боевой контракт.

`CombatCore.abilityTargetIndices(battle, mode)` возвращает упорядоченный список индексов **живых** кандидатов:
- `enemy` — текущий выбранный живой противник;
- `ally` — текущий выбранный живой союзник;
- `self` — текущий действующий живой герой;
- `all-enemies` — все живые противники в текущей волне;
- `all-allies` — все живые союзники.

При отсутствии активного действующего героя, неактивном бое, недопустимом режиме или мёртвой выбранной цели возвращается пустой список.

**Ограничение по безопасности:** `self`, `all-enemies` и `all-allies` пока **только просмотр потенциальных целей**. Эти режимы **не являются исполняемыми способностями**. Применение группового эффекта, упорядочивание событий, расход перезарядки, поражение нескольких целей и визуальные эффекты потребуют отдельного инкремента после согласования правил. Движок явно отказывает в исполнении неизвестного типа цели, а не случайно применяет групповое умение лишь к первому врагу.

Текущие однозначные способности продолжают действовать как раньше. `game.js`, обработчики касаний, анимации, AI, Save-001 и существующий баланс **не меняются**.

## [ПРЕДЛОЖЕНИЕ] Combat-011B — предмет согласования
1. Способности по себе (`self`): эффект только на исполнителя, без ручного выбора.
2. Групповые способности (`all-enemies`, `all-allies`): корректный проход по живым целям, событие на каждого затронутого бойца, один расход действия и одна перезарядка.
3. Порядок урона/лечения, смерть нескольких врагов, завершение волны и синхронизация анимаций требуют отдельной спецификации и тестов.
4. Первые демонстрационные способности/эффекты — отдельное решение владельца; без канонизации имен, чисел и статусов.

Возможные альтернативы:
- **Одна групповая атака сразу** — наглядная механика, но риск преждевременного баланса.
- **Сначала надёжный резолвер, затем реальное групповое действие** — меньше рисков для iPhone Safari и анимаций. Рекомендован этот путь.

## Combat-011B — выполнение способностей с несколькими целями

**[В РАЗРАБОТКЕ] Технический инкремент, не окончательный баланс.** Для автоматических тестов в `ability-data.js` введены четыре определения с ID `test-*`. В `HEROES`, интерфейс и кампанию они не добавлены.

- `self`: защита действующего героя (тест).
- `all-allies`: лечение всех живых союзников (тест).
- `all-enemies`: урон всем живым врагам, включая проверку уже действующих эффектов защиты и ослабления (тест).
- Одно групповое применение тратит **одно действие**, одну перезарядку и 1000 инициативы; событие `ability` единичное, события `damage`/`heal`/`effect`/`death` — отдельно для каждой цели в порядке построения отряда.
- Ослабление атакующего (`weakenAttacks`) снижает урон всем получателям групповой атаки и расходует одно применение после всей группы. Защита цели (`guardHits`) тратится независимо для каждого бойца.
- Мёртвые бойцы исключаются из списка до применения; при пустом списке команда отклоняется без списания действия/кулдауна и без очистки журнала.
- Проверка завершения сражения и перехода к следующей волне выполняется **после** обработки всех целей.
- `ability` содержит прежнее поле `targetId` первого получателя для совместимости анимаций, а также `targetIds`; журнал перечисляет цели.
- Новые комбинации (`all-enemies`+лечение и `all-allies`+урон) запрещены, чтобы случайно не внедрить неподтверждённые правила.
- Новых UI-кнопок, доступных боевых способностей, персонажей и чисел в действующем составе не появляется.

**[ПРЕДЛОЖЕНИЕ] Последующий шаг:** согласовать первое реально доступное массовое умение, его тип, силу и стоимость, затем отдельно подключить к мобильному интерфейсу, курсорам и 3D-анимациям.
