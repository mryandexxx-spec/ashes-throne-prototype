# Combat-012A — технический контракт мощных способностей

**Статус:** [В РАЗРАБОТКЕ] до CI, слияния и приёмки. Основа: GDD 3.0, Combat Specification 1.0 и решение владельца от 6 ноября 2026 года.

## Утверждённое решение

**[УТВЕРЖДЕНО] Вариант A:** мощная способность (`powerful`) использует собственную независимую перезарядку, а не новый ресурс или шкалу заряда. Временные тестовые числа и конкретные мощные навыки не утверждены. Проектная записка в PR #66 остаётся [ПРЕДЛОЖЕНИЕ] и не подлежит слиянию без разрешения.

## Реализация Combat-012A

- `AbilityData.get(actor,"powerful")` возвращает определение **только** для неигрового тестового ID `test-powerful-damage`. Такой персонаж не добавляется в `HEROES` и не доступен на экране подготовки.
- `CombatCore` хранит отдельный `powerfulCooldown` у бойца, начальное значение — 0. `specialCooldown` остаётся самостоятельным.
- При успешном применении `powerful` запускается только его собственная перезарядка; при успешном другом действии мощная перезарядка уменьшается на один. Аналогично специальная способность: при любом другом успешном собственном действии уменьшается её собственный счётчик. Событие врага ничего не уменьшает у союзника. **Это временное правило первой технической модели, а не утверждённая окончательная формула.**
- Действие тратит один ход, инициативу, и порождает обычные события `ability`, `damage`/эффект, смерть/исход по уже существующему контракту. Соответствующая анимация `powerful` уже предусмотрена системой слотов.
- Неизвестный ID, отсутствие определения, неготовая способность или неподдерживаемые параметры отклоняются **до** расхода хода, изменения событий или перезарядки.
- Состояние героя, в том числе обе перезарядки, сохраняется при переходе между волнами; новый бой начинает их с нуля.
- `game.js`, интерфейс двух кнопок, курсоры, 3D, AI, Save-001 и характеристики игрового отряда не меняются.

## Проверки

`tests/combat-012a-powerful-core.test.js`: первый тестовый мощный удар, отсутствие его у обычных героев, независимость перезарядок, блокировка на кулдауне, однократный расход хода, журнал, анимационная очередь, завершение волны и боя, повтор, сохранение прежних специальных умений.

Остальные регрессионные тесты запускает GitHub Actions через `npm test`. Это не заменяет проверки браузера и iPhone. Поскольку новые действия в UI не включены, на мобильном устройстве проверяются отсутствие регрессий базовой/особой кнопок и соблюдение одного курсора.
