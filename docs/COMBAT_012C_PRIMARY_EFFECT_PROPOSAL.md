# Combat-012C — дополнительный эффект основной цели

**Статус:** [ПРЕДЛОЖЕНИЕ], 6 ноября 2026 года. Этот документ — предмет согласования, а не утверждение механики, конкретных навыков или чисел. Основа: утверждённый GDD 3.0 § 9.4–9.6, Combat Specification 1.0, Combat-011C-HF1 и принятый Combat-012B.

## 1. Исходное состояние и проблема

- В ручном бою игрок выбирает **одного** живого врага; один курсор показывает основную цель. Это утверждённое поведение Combat-011C-HF1.
- Массовая атака с `target:"all-enemies"` воздействует на **всех живых противников** и фиксирует `ability.primaryTargetId` и `targetIds` в событиях. Выбранный враг не должен ограничивать сам список массовых целей.
- Сейчас у `performMultiTargetAbility` параметр `weakening` применяется **всем выжившим** получателям группового урона. Он **не подходит** для бонусного ослабления только одной цели.
- В Combat-012B у всех пяти доступных союзников есть временные мощные умения; их параметры, состав и поведение уже приняты владельцем как работающая демонстрация, но **не окончательный баланс/канон**.
- GDD не определяет конкретный комбинированный навык и порядок разрешения таких эффектов.

## 2. Два подхода

| Подход | Преимущества | Риски |
|---|---|---|
| **A. Узкое `primaryWeakening` для групповой атаки** | Минимальная правка существующего группового резолвера, повторное использование `weaken` и готовых событий/анимаций, легко тестировать | Не описывает все будущие уникальные бонусные эффекты |
| **B. Универсальная композиция эффектов с условиями и целями** | Более выразительная модель для будущих персонажей и синергий | Преждевременный рефакторинг боевого движка и необходимость согласовать множество новых правил |

**Рекомендация:** начать с A, без нового статуса, ресурса или универсального движка эффектов. Если более сложные комбинации действительно потребуются в Combat-013, расширять на фактических примерах.

## 3. Предлагаемое правило A — строго для тестового вертикального среза

1. У тестового определения групповой атаки может быть дополнительное поле `primaryWeakening: 2`. Значение **2 тестовое**, не окончательный баланс. Допустимо только для `target:"all-enemies"` + `kind:"damage"`; другие комбинации отвергать без расхода хода.
2. Сначала один раз определяется набор **живых** противников и основная цель: текущий `selectedEnemy`, если она входит в этот набор; иначе первый живой противник. Основная цель остаётся одной, несмотря на массовое действие.
3. Базовый урон наносится всем живым противникам в обычном порядке; сначала завершается цикл базового воздействия. События `damage` и `death` сохраняют существующий формат.
4. **После** цикла урона, **до** определения победы/следующей волны, основная цель получает `weaken` только если всё ещё жива. Если погибла — бонус **не переносится** другому врагу; по мёртвой цели событие эффекта не создаётся.
5. Бонус увеличивает оставшееся число ослабленных атак как `max(текущее, primaryWeakening)`, чтобы более сильное ранее наложенное ослабление не ухудшалось. Событие `effect` с `targetId:primaryTargetId` отражает итоговое значение. Другие противники бонусного ослабления не получают.
6. Вся команда по-прежнему стоит **один** ход и одну перезарядку. Ослабление атакующего расходуется по уже действующему правилу один раз за массовую команду, не за каждую цель. Порог инициативы, переход волны и автобой не меняются.
7. Удержание кнопки способности явно объясняет: «Урон всем живым врагам; выбранная цель дополнительно получает ослабление на N атак». Игрок не должен гадать, почему один враг получает больше эффектов.
8. Ни один **ныне доступный** навык Каэля, Лиры, Дарина, лекаря или учебного бойца не меняется автоматически. Для первого теста используется **отдельный технический `test-* ` ID** без добавления в `HEROES`; только после технической проверки и отдельного решения владелец выбирает, делать ли такой навык доступным в интерфейсе.

## 4. Тесты и риски

Автотесты для последующего кодового PR должны покрыть:
- два и более живых врага: базовый урон всем, эффект лишь выбранному другому врагу, `primaryTargetId` и `targetIds` корректны;
- убийство основной цели: нет `effect` по трупу и переноса бонуса на другого;
- убийство последнего врага: один `battle-end`, никакой новой волны до завершения группы;
- смена волны: новый противник не наследует бонус от погибшей основной цели;
- наличие старого ослабления `weaken`: сохраняется максимум, не обнуляется;
- защиту `guard`, ослабление самого атакующего, сортировку событий, одну перезарядку и одно действие;
- неправильное поле/тип способности: нет потери хода, инициативы или изменения журнала;
- отсутствие регрессий уже принятых `basic`, `special`, `powerful`, автодействия, анимаций смерти, одного курсора и iPhone landscape.

**Мобильный чек-лист после возможной публикации:** сверить версию в футере, коснуться другого противника и убедиться в одном курсоре, применить демонстрационную комбинацию, проверить урон всем/ослабление только выбранному, смерть выбранного, волны, повтор, подсказку удержания и 1×/2×/4×. Реальный iPhone нельзя считать проверенным на основании CI.

## 5. Решения владельца

**Требуется явное решение:** утвердить для Combat-012C **узкий вариант A** как первый технический механизм (групповой урон + бонусное ослабление *только живой выбранной основной цели*, без переноса бонуса при её смерти), либо выбрать B, либо отказаться от этого инкремента и переходить к Combat-013.

Если вариант A утверждён, первый кодовый PR должен ограничиваться движком, `AbilityData` и автотестами — **без смены уже принятого игрового набора**. Доступный игроку демонстрационный навык вводить только после отдельного решения.
