# Combat-012 — мощные способности: предложение к утверждению

**Статус:** [ПРЕДЛОЖЕНИЕ], 6 ноября 2026 года. Не заменяет GDD 3.0 или Combat Specification 1.0. Пока ни одна новая мощная способность, её стоимость или числовой баланс не утверждены.

## 1. Что уже утверждено

По GDD 3.0 §§ 9.4–9.6 и Combat Specification 1.0 §§ 1, 5:
- В ручной ход герой должен иметь выбор базовой, специальной и **мощной** способности при выполнении условий доступности. Пассивная и лидерская — автоматические.
- Самостоятельный выбор цели, шкала инициативы и мобильная читаемость важнее зрелищности.
- Формулы, стоимость, сроки перезарядки, эффекты и конкретные наборы способностей остаются **TBD**.

По коду `main` после Combat-011C-HF1:
- `AbilityData.get(actor, id)` возвращает только `basic`/`special`; `CombatCore.abilityReady` и `performPlayerAbility` ожидают те же два варианта.
- `specialCooldown` существует; новых индикаторов ресурсов нет.
- Движок Combat-011 умеет `enemy`, `ally`, `self`, `all-enemies`, `all-allies` и сохраняет `primaryTargetId` выбранного противника.
- На арене есть две кнопки; третья потребует мобильной проверки ширины, долгих нажатий и safe-area. Автобой применяет только базовую атаку.
- `SaveCore` хранит прогресс вне боя; изменять его схему для способности не требуется.

## 2. Варианты условия доступности

| Вариант | Правило [ПРЕДЛОЖЕНИЕ] | Плюсы | Риски |
|---|---|---|---|
| A — отдельная перезарядка | У мощной способности собственный счётчик `powerfulCooldown`, независимый от `specialCooldown`; уменьшается при завершении **собственных** ходов героя | Прозрачно, не требует третьего ресурса, использует существующий подход; удобен для первого вертикального среза | Нужно согласовать стартовую готовность и величину перезарядки |
| B — шкала заряда | Удары/действия наполняют отдельный заряд, мощная способность его расходует | Вводит тактику накопления, отличает мощную способность от специальной | Дополнительная математика, HUD, крайние случаи при смерти/волнах; риски для iPhone |
| C — событийное условие | Доступна после заданного события (защита союзника, убийство врага, накопление эффектов) | Сильная связь с ролью героя | Зависит от ещё не реализованных триггеров и пассивных эффектов Combat-013 |

**Рекомендация:** A для Combat-012A–012C как *временной модели*, не окончательный баланс. B и C оставить как возможные индивидуальные правила в будущем, не добавлять сейчас.

### Отдельные решения, требующие утверждения

1. **Стартовая доступность:** мощная способность готова с начала боя / требует `N` собственных действий до первого применения. Для обучающего сценария предложена готовность с начала, чтобы её можно было проверить сразу.
2. **Отсчёт:** один собственный ход уменьшает мощную и специальную перезарядки независимо; использование одной способности не должно обходить ограничения другой. Умения не должны автоматически применяться.
3. **Первый обучающий эффект:** безопасный демонстрационный удар выбранной одиночной цели, использующий существующий `damage`-резолвер. Числа (множитель, число ходов ожидания) назначить только для тестового бойца, не переносить в канон.
4. **Выбор основной цели при массовом воздействии:** в любой момент **только один курсор выбранного противника**. Способность может воздействовать на всех, но дополнительный эффект на основную цель вводится только отдельным одобрением (это предложение владельца после Combat-011C).

## 3. Рекомендуемое безопасное разбиение работ

### Combat-012A — контракт движка без изменения пользовательского боя
- `AbilityData` может возвращать `powerful` **только для специальных тестовых бойцов**, отсутствующих в `HEROES`. Нет `powerful` для текущего игрового отряда до согласования.
- Отдельный счётчик `powerfulCooldown`; никаких новых зависимостей или сетевых запросов.
- Доступность и расход одного действия реализованы на существующем пути `CombatCore.performPlayerAbility`. Для команд с неизвестными/неподдерживаемыми эффектами — отказ без траты хода.
- Тесты: отсутствие определения; независимость кулдаунов; занятость хода; сохранение при волнах; смерть, победа, поражение и повтор; корректное событие `abilityId: "powerful"`, совместимость с логом и анимацией.
- UI, сохранения, герои и баланс **не меняются**. Если потребуется отображаемая версия, обновить `package.json` и футер.

### Combat-012B — один доступный демонстрационный мощный навык
- Добавить только после утверждения типа доступа и временных правил.
- Третья кнопка на существующей панели; disabled и счётчик; долгим нажатием — описание доступности и целей.
- Сохранить один курсор основной цели и возможность выбрать её касанием. При одиночной атаке сразу применять по выделенному врагу.
- На узких iPhone landscape добиться площади касания не ниже текущих договорённых минимумов; проверить футер, safe-area и переполнение.
- Автобой оставляет базовую атаку, пока AI-правила Combat-015 не согласованы.

### Combat-012C — особые сочетания воздействий (отдельное согласование)
- Возможный сценарий: урон всей группе плюс отрицательный эффект **только выбранной основной цели**.
- Проверять обработку смерти основной цели, порядок событий, цель после смены волны, перезарядку и 3D-анимации.
- Не вводить новый статус или числовую формулу исключительно ради демонстрации.

## 4. Критерии приёмки

- Никаких изменений поведения уже принятых базовых и специальных способностей.
- За один ход можно применить только **одно** действие; невозможно применить неготовое или неизвестное умение.
- Отдельные счётчики не сбрасываются при переходе между волнами; корректно сбрасываются при новом бое.
- Нет ложных курсоров при смене активного героя, индикаторы погибших исчезают после анимации.
- Автотесты, GitHub Pages после merge, затем реальная приёмка iPhone Safari. Первым делом сверить номер сборки в футере.
- Модельная/CI-проверка не равнозначна браузерной или мобильной.

## 5. Решение владельца

**[ПРЕДЛОЖЕНИЕ]** Утвердить только стратегию первого инкремента: вариант A (независимая перезарядка, без нового ресурса), Combat-012A с тестовым определением и без новых доступных игроку способностей. Стартовую готовность и конкретный игровой навык согласовать перед Combat-012B.

После утверждения выполнить разработку в отдельной ветке, тесты и PR. Не сливать без отдельного разрешения.
