# Combat-014A — добровольное назначение лидера и тестовый бонус отряду

**Статус:** [В РАЗРАБОТКЕ] до CI, merge и проверки владельцем. Тестовые значения не являются утверждённым балансом, а тестовые имена не являются персонажами канона.

## Исходные правила

**[УТВЕРЖДЕНО]** GDD 3.0, §9.1–9.4: у всех героев есть пассивные способности, у **некоторых** дополнительно лидерские; эффекты включаются автоматически, без отдельного действия игрока. Существующий Combat-013B уже рассчитывает плоские модификаторы атаки и скорости. Каэль, Лира, Дарин и два учебных героя пока **не назначены лидерами**.

## Технический контракт [ПРЕДЛОЖЕНИЕ]

`CombatCore.createBattle(heroes, futureWaves=[], {leaderId:"test-leader-aura"})` принимает необязательное, **явное** назначение одного лидера, указанного существующим ID живого союзника в стартовом составе. Если `leaderId` отсутствует, бой идёт **без лидера** — исходные вызовы остаются рабочими.

- Проверка на старте: лидер должен быть живым членом союзного отряда и иметь определение `AbilityData.get(hero,"leader")`. Нельзя назначить противника, отсутствующего бойца, не-лидера или пустой/неподходящий ID. Ошибка выявляется при подготовке, а не во время боя.
- Лидерское умение описано **данными**, а не условием `hero.id` внутри движка. Для технической проверки `modifiers:[{stat:"atk",operation:"flat",value:4,scope:"all-allies",when:{kind:"always"}}]`. `scope:"self"` действует только на лидера; `all-allies` — на всех живых союзников, в том числе лидера.
- `CombatCore.activeLeaderModifiers(battle,recipientId)` вычисляет доступные бонусы без мутации героя. При расчёте `effectiveStat` лидерские плоские бонусы складываются с собственными пассивными бонусами бойца, затем применяется уже действующая нижняя граница атаки/скорости из Combat-013B.
- Аура действует **лишь пока назначенный лидер жив**. После его смерти бонус прекращается, лидерство не переносится другому герою. Если боец оживает в будущих механиках, данные допускают пересчёт, но правила воскрешения сейчас не утверждаются.
- Бонусы не затрагивают противников, мёртвых союзников и сохранённые базовые поля `atk`/`speed`. На следующих волнах состав лидеров не меняется; текущие HP, эффекты, инициатива и кулдауны продолжают работать по прежним правилам.
- В Combat-014A **не добавляется назначение лидера на экране подготовки**. В пяти игровых определениях `leader` по-прежнему `null`. Поэтому опубликованная демо-игра по умолчанию не получает никаких лидерских бонусов, кнопок или нового баланса.

## Проверки

`tests/combat-014a-leader-contract.test.js`: отсутствие назначенного лидера, запрет не-лидеров/врагов/несуществующих/мёртвых кандидатов, бонус каждому живому союзнику и только себе, совместимость с пассивками, неизменность исходных статов, реальный урон, сохранение ауры между волнами, отключение при гибели лидера, отсутствие кнопки. Полный `npm test` и CI.

**Версия среза:** `v0.3.24 · CBA014A`. После возможного merge проверить Pages и регрессию в мобильном браузере: текущий состав, три кнопки, выбор одного врага, волны, гибель, перезапуск, автобой 1×/2×/4× и safe-area в landscape. Пока нет новых визуальных лидерских механик; тестовые бойцы в UI недоступны.

## Открытые авторские решения

**[ПРЕДЛОЖЕНИЕ] Combat-014B** — проектирование выбора позиции лидера в UI, в том числе доступности лидеров и правил сохранения выбора. Вопрос о продолжении действия лидерской способности после гибели, смене лидера в бою, областях воздействия (отряд/фракция/уникальные цели) и собственных синергиях нельзя считать утверждённым по результатам этого теста. Действующая модель остановки ауры при смерти лидера — **только безопасное техническое допущение**, которое может быть пересмотрено владельцем до создания канонических лидерок.
