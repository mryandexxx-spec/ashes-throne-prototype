# ENV021 — реальные сторонние скальные ассеты, реальный Babylon WebGL

**Состояние:** [РЕАЛИЗОВАНО И ТЕХНИЧЕСКИ ПРОВЕРЕНО] импорт внешнего скального 3D; **[ХУДОЖЕСТВЕННО ОТКЛОНЕНО]** итоговая композиция ущелья; **[ПРЕДЛОЖЕНИЕ]** любые дальнейшие действия. Ветка — Draft PR #208, не main. Арена — неканонический тест.

## 1. Происхождение, лицензии и воспроизводимость

1. **Poly Haven, Coastal Cliff 02**, авторский природный фотосканированный 3D-ассет: https://polyhaven.com/a/coastal_cliff_02; лицензия CC0 https://polyhaven.com/license. Официальная API выдача файлов: https://api.polyhaven.com/files/coastal_cliff_02. Исходные `coastal_cliff_02_1k.gltf` (3220 B), `coastal_cliff_02.bin` (26 773 008 B) и `coastal_cliff_02_diff_1k.jpg` (759 723 B) скачиваются **только при сборке** через GitHub Actions и сверяются с контрольными суммами MD5, опубликованными API. Исходник НЕ лежит в игровом репозитории и НЕ загружается в мобильном браузере.
2. `tools/env021-optimize-polyhaven.py` в воспроизводимой сборке упрощает настоящие треугольники фотоскана через `fast-simplification` (не генерирует камень заново), переносит пиксели исходной карты на вершины и экспортирует `assets/env021/PolyCliff01.glb`: **229 832 байта, 6057 вершин, 11 000 треугольников**, цвет вершин. Экспериментально это гораздо лучше исходного многомиллионного скана для мобильной сцены. Используются три размещения этого GLB, значит около **33 000 треугольников из этого ассета** помимо существующей арены; общий FPS пока НЕ измерен.
3. **Gobkit Free 3D Assets** (репозиторий: https://github.com/Ariescar/gobkit-free-assets, лицензия CC0: https://github.com/Ariescar/gobkit-free-assets/blob/main/LICENSE). Три `Cliff00*.glb` и `Rock001.glb` первоначально получены из закреплённой upstream ревизии `4e73c68fa6e8ca9d948fcc0ce7215c830a022c3b`, проверены по структуре/лицензии. Каждый имеет примерно 16 треугольников. Их слишком грубая форма и яркая палитра при реальном просмотре были отклонены. Они **не используются финальной runtime-композицией ENV021**, но пока сохранены в экспериментальной ветке как сравнение; ничего из этого не публиковалось.

## 2. Реализованный способ встраивания

`combat-environment-017.js` в текущей экспериментальной ветке загружает только локальный `assets/env021/PolyCliff01.glb`. Малый ограниченный glTF2/GLB парсер читает реальные атрибуты POSITION, индексы, NORMAL/UV при наличии и COLOR_0 с учётом нормализации. Проверяются GLB header, chunk length, ограничения числа вершин/индексов, конечность чисел и границы буфера. Никакого Babylon loaders bundle или сторонней зависимости в runtime.

В существующей Babylon Scene создаются три обычных `Mesh` с настоящей геометрией Poly Haven, с фиксированными координатами относительно камеры и без взаимодействия при касании. Ресурсы получают прежнее scene-owned управление. Асинхронный `Promise.all` загружает **один раз на сцену** (никакого нового цикла рендера). Фоновые кольца ENV009 отключаются **только после полной удачной загрузки**; старая стабильная `living_ledge` остаётся под бойцами. При ошибке импорта маркер `env021Assets=fallback`, исходная арена должна оставаться пригодной для боя. Позиции бойцов, HUD, camera alpha/beta, сохранения, боевые правила и `?environment=env010` не изменены. Не добавлялись сооружения, растительность, элементы канона.

## 3. Фактические проверки

- [Actions WebGL/Node для внешнего GLB](https://github.com/mryandexxx-spec/ashes-throne-prototype/actions/runs/42702506591): **209/209 Node PASS**, настоящий Chromium/Babylon full-game WebGL с полным HUD 844×390 при radius=12/19 **PASS**. Тест подтверждает загрузку именно внешних мешей и отключение старых далёких колец, не только создание DOM-заглушки.
- [Настоящие PNG + DOM в GitHub Artifact](https://github.com/mryandexxx-spec/ashes-throne-prototype/actions/runs/42702506591/artifacts/13712056772) сняты в default/far и фактически просмотрены.
- Проверена лицензия источников, ограниченный перенос модели в локальный файл и то, что загрузка не требует интернет-подключения к Poly Haven в ходе игры.
- **Не проверено:** реальный iPhone Safari, FPS, GPU memory, нагрев, касание/pinch/перезапуск, два полных боевых цикла, визуальная приёмка владельцем.

## 4. Художественный вердикт по настоящим кадрам

**[ART REJECTED]** В первой пробе микроскопические Gobkit модели выглядели красно-чёрными искусственными блоками. После перехода на Poly Haven краски стали настоящими каменными, рельеф читается значительно лучше, но исходная фотоскала имеет геометрию **широкой и тонкой полосы** (после оптимизации 12×2.94×2.49 условных единиц). В fixed-camera кадрах создаёт отделённые плоские каменные стенки, а оставшаяся округлая `ENV009 living_ledge` продолжает выглядеть как остров. Даже после увеличения высоты и глубины формы **разрыв между полкой и берегами не выглядит природным глубоким ущельем**. Сцена работоспособна, но в art-main **не годится**.

**Вывод:** гипотеза о внешних ассетах подтвердилось технически: качественная скальная поверхность действительно может быть импортирована и оптимизирована автоматически, с CC0 и малым размером. Но отдельная фотоскала не может заменить цельную природную топологию ущелья. Следующий шаг — искать **полноценный береговой скальный массив со связной полкой**, а не набор тонких фотосканированных стенок, и согласовать экранный силуэт прежде расширения окружения. Не подменять художественный результат успехом CI.
