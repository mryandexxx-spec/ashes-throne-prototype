# ENV023 — цельная готовая CC0-модель ущелья: исследовательский итог

**Статус:** [ПРЕДЛОЖЕНИЕ], [ТЕХНИЧЕСКИ ПРОВЕРЕНО ЧАСТИЧНО], [ХУДОЖЕСТВЕННО НЕ ПРИНЯТО]. Все изменения только в Draft PR #210; **main и канон не менялись**.

## Источник

Готовый внешний ассет **Continuous Gorge Escarpment Configuration** от [3DAssets.dev](https://3dassets.dev/assets/gorgehold-survivor-gallery-and-operations-broken-road--11140b6c), издателем указан **CC0 1.0 Universal**. Прямой файл [model.glb](https://cdn.3dassets.dev/assets/32899/v1/model.glb), 5 328 064 байта. Сообщённое происхождение — 3D-модель из AI-assisted постапокалиптического набора; никакие предметы, сюжеты или лор набора в игру не переносились. Лицензия задокументирована издателем, но источник **не утверждает** какой-либо канон «Пепельного престола».

Веткой получен исходный файл, проверены GLB заголовки и топология: **86 245 треугольников / 36 мешей**. Через `@gltf-transform/cli dequantize` успешно устранён `KHR_mesh_quantization`, получены реальные размеры ~33×12.6×45 м. Тестовая карта вверх обращённых граней показывает несколько уровней обоих берегов. Исходник сохранён только в экспериментальной ветке.

## Оптимизация и реальный WebGL

`tools/env023-optimize-complete-gorge.py` переносит оригинальные треугольники и цвета, упрощает 36 частей, объединяет их в локальный GLB **1 448 212 байт / 25 062 треугольника / 71 656 вершин**. Импортёр `combat-environment-017.js` в отдельной ветке считывает собственный локальный GLB, проверяет нормализованные цвета, ограничения буфера и индексы, и отключает старую округлую арену только после полной загрузки нового меша. Ни одно игровое правило, герой, CombatCore, HUD, камера или ENV010 не менялись.

[Реальный GitHub Actions WebGL](https://github.com/mryandexxx-spec/ashes-throne-prototype/actions/runs/42709153040) + [PNG/DOM artifact](https://github.com/mryandexxx-spec/ashes-throne-prototype/actions/runs/42709153040/artifacts/13715201576): **208/208 Node PASS**, Chromium Babylon actual game full HUD 844×390, normal/far **PASS**, новый меш загружен, исходная арена скрыта. **Но** изображение сильно испорчено многочисленными чёрными и светлыми треугольными полосами. Контроль с нейтральным материалом сохранил дефект — это не просто проблема окраски.

Отдельный **unsimplified** контроль загружает после конверсии **86 245 исходных треугольников, 214 595 вершин**, ~4 469 652 байта с нейтральными цветами. Первичная проверка тяжёлой версии не прошла из-за слишком большой встроенной текстуры; после принудительного удаления текстур Node-парсер подтвердил корректные индексы и фактический WebGL маркер `ready`. [GitHub Actions unsimplified](https://github.com/mryandexxx-spec/ashes-throne-prototype/actions/runs/42709946103) + [artifact](https://github.com/mryandexxx-spec/ashes-throne-prototype/actions/runs/42709946103/artifacts/13715706976): нормальный ракурс отрисовал **связную** поверхность, а не рассыпанные фрагменты, однако кадр представлял преимущественно огромную тёмную массу. Прогон workflow как целое отмечен **failure** по порогу PNG для второго ракурса, поэтому **не выдавать его за полностью пройденный WebGL двух ракурсов**. Реальный iPhone Safari, FPS, тепловая нагрузка, касания/полный бой не проверялись.

## Технический и художественный вывод

1. **Готовая целая 3D-модель ущелья доступна законно и может быть импортирована** при соответствующем преобразовании glTF. Это не процедурная имитация.
2. Нынешний простой офлайновый метод `fast_simplification` по отдельным 36 частям **не сохраняет пригодный силуэт**: возникают рваные треугольные полосы; это доказано сравнением с неупрощённой версией. Не утверждать, что оригинальный издательский GLB дефектный.
3. Неупрощённый вариант велик для мобильного браузера и не даёт хорошей композиции в нынешнем кадрировании. Следующий эксперимент должен сначала сохранить топологические границы при оптимизации, одновременно выбрать выгодный видимый участок берега и достаточное место для бойцов.
4. **Художественная приёмка отрицательная**. Не сливать этот PR; не использовать текущий оптимизированный файл в опубликованной игре. Другой выход — искать законченный CC0-массив, изначально предназначенный для камерного боя с верхней полкой, с меньшим количеством отдельных компонентов.
