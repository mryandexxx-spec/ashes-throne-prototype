# ENV025 — проверка готового природного скального уступа по настоящей сетке

**Статус [ПРЕДЛОЖЕНИЕ / В РАЗРАБОТКЕ] — НЕ ХУДОЖЕСТВЕННО ПРИНЯТО.** Эксперимент находится только в [Draft PR #213](https://github.com/mryandexxx-spec/ashes-throne-prototype/pull/213), `main` и приватный канон не менялись.

## Первичные критерии

Отбор производится до интеграции в Babylon: (1) настоящая естественная, не прямоугольная цельная береговая форма, (2) достаточная натуральная верхняя контактная зона, (3) обрыв с существенным перепадом высот и пустота справа от бойцов в утверждённом fixed-camera full HUD, (4) доступная оригинальная лицензия CC0, (5) реальная низкополигональная версия с сохранённым рельефом, а не процедурно добавленные стены.

## Кандидаты, источники и проверки

**Poly Haven Coastal Cliff 04** — https://polyhaven.com/a/coastal_cliff_04. CC0, авторы Rob Tuytel и Rico Cilliers, настоящая фотосканированная скала с неровной верхней кромкой. Проверены официальные API `https://api.polyhaven.com/files/coastal_cliff_04` и исходный бинарник по MD5 `77612519fa9eb44129ba40943612c3c3`. Один glTF mesh `Plane.002` (без подставных generated-плоскостей), **1 537 926 треугольников, 789 032 вершины, размеры 86.78×11.00×24.25 м**, исходный BIN 43 704 136 байт. Уровни 1K/2K/4K/8K в официальном **glTF** меняют текстуры, но ссылаются на один и тот же полный 43.7MB BIN: **готовый лёгкий glTF-LOD не подтверждён**. Возможность LOD в исходном Blend не проверена.

Геометрическое обследование `tools/env025-screen-true-cliff-geometry.py` в настоящем GitHub runner: верхняя скала содержит **279 830 граней с близкой к горизонтальной ориентацией**, в двухметровой дискретизации 214 занятых ячеек на высотах верхней четверти оригинального перепада. Для строго ограниченных локальных перепадов высоты обнаружено **25 потенциальных ровных зон размером 12×8 м**, лучший кандидат начинается в ячейке (8,-5), высота около **8.329 м**, разница медианных высот ячеек **0.451 м**. Это **только проверка геометрического потенциала по центрам граней**, ещё не подтверждение размещения всех бойцов, проекции кромки, коллизий или безопасности игры.

**Контроль 3DAssets.dev Posthouse Cliff Base** — https://3dassets.dev/assets/griffin-airmail-roost-and-posthouse-posthouse-cliff-ba-dab769ef — оригинальный CC0 GLB **30 268 байт / 1 536 треугольников**, 16.19×1.899×14 м. Имеет готовое верхнее плато и неровные каменные выступы, но **1.899 м высоты недостаточно** для основной глубокой пропасти в натуральном масштабе. Отложен, не интегрирован.

## Mobile-ready опыт

Ветка также содержит **`assets/env025/CoastalCliff04Mobile.glb`** — *не новый придуманный ландшафт*, а реальный Poly Haven mesh, упрощённый из тех же исходных треугольников в GitHub Actions скриптом `tools/env025-optimize-original-coast.py`, с переносом пикселей настоящего исходного диффузного фото (1K) на вершины. **40 000 треугольников / 21 652 вершины / 827 400 байт**, исходные габариты сохранены. После оптимизации на верхней полке выбранного 12×8м участка осталось **74.35 м²** направленных вверх скальных граней. Это предварительный mobile budget-кандидат без утверждённых FPS/LOD в Safari.

Проверочный `combat-environment-017.js` загружает именно этот **один локальный GLB**, не собирает регулярных плит, использует measured offset (source X=22, Z=-6, Y=8.329), сохраняет боевые координаты и существующий HUD, отключает старую овальную платформу только после успешной асинхронной загрузки. В случае ошибки сохраняется старая арена. Никакой сторонней runtime-зависимости и нового render loop не добавляется.
