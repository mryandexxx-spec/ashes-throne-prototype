# Combat-Events-001 — временный технический контракт

**Статус:** [РЕАЛИЗОВАНО] — PR #21 слит, CI успешно пройден, 8/8 проверок на iPhone Safari подтверждены владельцем; GitHub Pages опубликован после повторного запуска шага deploy. Не изменяет GDD и боевые правила.

## Назначение

`battle.events` — упорядоченный массив простых объектов по результатам **последнего успешно выполненного действия игрока и последовавших автоматических действий противников**. В новом бою массив пуст. Перед принятым действием игрока начинается новый набор. Недопустимое действие не меняет события. При первоначальном `advanceToPlayerTurn` события противников также записываются.

События не являются сохраняемым журналом: Save-001 их не записывает. UI пока продолжает читать `battle.message`. Позднее потребитель может использовать их для анимаций или журнала без повторного вычисления результата боя.

## Форматы

- `{type:"ability", actorId, targetId, abilityId}` — действие игрока или врага, до его результата. У врагов используется `basic`.
- `{type:"damage", actorId, targetId, amount, remainingHp}` — фактически вычисленный урон по существующим правилам (может превышать остаток HP цели); итоговое HP неотрицательное.
- `{type:"effect", actorId, targetId, effect, stacks}` — наложение `guard` или `weaken`; расходование существующего эффекта отдельно пока не фиксируется.
- `{type:"death", targetId}` — цель погибла от удара.
- `{type:"battle-end", winner}` — результат `ally` или `enemy`; только при завершении.

Порядок внутри одного действия: способность → урон → смерть или наложение эффекта → возможный итог боя. Между ходами врагов порядок сохраняется. Новых боевых механик, логов на экране и анимаций в этом этапе нет.

**Приёмка:** существующие тесты плюс проверка порядка, значений урона и нескольких ходов врага; затем iPhone Safari после разрешённого слияния.
