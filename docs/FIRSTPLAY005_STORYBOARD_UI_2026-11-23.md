# FIRSTPLAY005 — постановка и диалоговый UX первого донесения

**Дата:** 23.11.2026. **Статус художественного решения:** [ПРЕДЛОЖЕНИЕ]. Техническая реализация не утверждает новый канон.

## Ошибка FIRSTPLAY004

Сочетание полноэкранного фонового matte painting и отдельно поверх него поставленной *высокой иллюстрированной карточки* героя разрушало сцену: портрет занимал значительную часть кадра, имел собственный фон и собственную подпись, перекрывал вид места происшествия. Реплики рабочего и мастера сопровождались одним и тем же общим планом — действия на мосту не было видно. Успешные автоматические тесты проверяли соответствие названий портретам, но не качество композиции.

## Исправление

1. **Единый диалоговый слой** внизу: маленькое портретное окно или нейтральный знак роли, имя говорящего, реплика. Герой больше не имеет отдельного плаката в середине кадра. Портрет Рена/Арта берётся **только из уже используемого игрового файла**.
2. **Разные планы без генерации новых лиц:** панорама города и настила, приближение к рабочим, осмотр опор, нижний обход, общий план при решении командира. Связка «кадр → говорящий → текст» задаётся в данных сцен \`shot\` и \`speakerId\`.
3. **Простое управление:** прежние два выбора, тактические эффекты, бой, эпилог, пропуск, повторный запуск остаются неизменными.
4. Портрет не должен занимать более 80×80 CSS px на целевых landscape-экранах и должен целиком находиться **внутри** диалоговой панели. Имя не дублируется отдельным текстом поверх изображения.
5. Работа с ассетами: *новых полнофигурных героев не рисуем*. Панорама \`assets/cutscenes/first-report/v3/bridge-approach.*\` — уже находившийся в игре визуальный [ПРЕДЛОЖЕНИЕ], а не утверждённая топография Садов.

## Критерии

- На первом кадре есть читаемый смысл действия у рабочего (план с приближением к настилу).
- При смене Арта на Рена вся важная информация читается за один взгляд: портрет + имя + реплика, без большой лишней рамки.
- На 844×320, 844×390, 932×430 не режет нижнюю панель, кнопки выбора доступны, основной текст крупный; \`safe-area\` соблюдена.
- Reload, два разных приказа, бой/результат, возвращение в штаб и подтверждённый сброс проходят **через реальные состояния игры**; успех теста не равен приёмке эстетики.
- iPhone Safari на физическом устройстве, канон новой иллюстрации и художественная приёмка — отдельные статусы.

## Риск

Смена плана с одной панорамы — **минимальная исправляющая итерация**, а не полноценный набор покадровых рисунков. В будущем художественные кадры для каждого действия можно заменить независимо от механики, не возвращая «вклеенные карточки».
