## Решение и границы
Два маленьких **чистых модуля JavaScript** без зависимостей, DOM, Babylon.js, localStorage или побочных эффектов:
- \`gear-source-data.js\`: источники по \`materialId\`, полученные **только из живых** \`MissionData.all()\`, \`CampaignData.getMission()\`, \`ProgressCore.MISSION_GEAR_FARM\` и \`missionEnergyCost()\`. Нет второго списка дропа, миссий или собственных цен. Проверка целостности ссылок \`catalogIssues()\`. Доступность — \`CampaignData.available()\`, завершение и звёзды — из уже существующего \`campaignProgress\`; никакого отдельного сохранения.
- \`gear-planning-core.js\`: неизменяющий состояние расчёт конкретного слота \`plan(progress,heroId,slotId,campaign)\`, полного текущего ранга \`planTier(progress,heroId,campaign)\` и \`findSources(materialId,progress,campaign)\`. Использует \`ProgressCore.itemOffer\`, \`canEquipItem\` и конечные \`item.ingredients\` из \`GearData\`; композиты уже разложены на семь физических материалов. Возвращает \`have/need/missing\` для каждого компонента и валюты, состояние слота и реальные источники.

## Контракт источника
- \`access=unknown\`: состояние прохождения не передано или некорректно, не делать вид, что миссия открыта.
- \`access=locked\`: не выполнены требования кампании; \`missingPrerequisites\` содержит настоящие missionId.
- \`access=first-clear\`: первый вход в миссию при v3 бесплатен; при победе существующий \`game.js\` вызывает \`grantRepeatFarm\` **включая первую победу**. Инструмент показывает этот фактический путь, но не меняет награды.
- \`access=repeat\`: победа уже была, ручной повтор возможен с 1★, расходует текущую стоимость энергии.
- \`simulationUnlocked\`: только при уже пройденной миссии и \`bestStars===3\`; \`canSimulate\` также учитывает переданное количество энергии.
- \`quantity\` и \`currencyPerVictory\`: текущие гарантированные награды демонстрационных миссий, не обещание будущей экономики. \`runsForDeficit\` — простая арифметика количества **побед**, без предположения об их вероятности; \`nominalEnergyForDeficit\` — консервативная стоимость *оплачиваемых* заходов, **не прогноз фактически потраченной энергии** (первый вход бесплатен, есть неудачные попытки и регенерация).
- Нет скрытых шансов выпадения: текущий тестовый повтор детерминирован.

## Контракт планировщика
- Шесть слотов, один существующий предмет на класс/слот/ранг G1–G13; отсутствующая или неоднозначная позиция даёт \`null\`, а не выдуманный рецепт.
- \`status=ready/missing/installed\` для слота, \`ready/missing/complete\` для комплекта. Уже установленный предмет больше **не требует повторной покупки**.
- \`planTier\` суммирует цены **только пустых слотов** и вычитает единый склад **однократно**, что не допускает ложного обещания «хватит на все шесть», если на каждый слот по отдельности хватало.
- Переход на следующий G — отдельный платный шаг \`promotion\`, **не** включён в стоимость комплекта; уровневый gate не вводится.
- Возвращаемые объекты и списки \`Object.freeze\`; изменения прогресса, расходование энергии и сохранения выполняются существующими транзакционными обработчиками, **не** Finder.

## Что сознательно не внедряется
- **Никаких новых выпадающих предметов, материалов, валют, цен, миссий, шансов, G-ограничений**.
- **Нет UI**: эти модули пока не подключены через \`index.html\`/\`game.js\`, поэтому опубликованная сборка, футер и кэш останутся \`v0.3.181 · GEARSAFE002\`. Это подготовленное проверяемое API для следующего UI-этапа, который владелец согласует **отдельно**.
- Не меняются схема v3, режимы кампании/сюжета LC-008, магазины, модели и 3D.
- Никакого автоматического запуска симуляции: только проверенная доступность по уже имеющимся правилам.

## Регрессионные критерии
\`tests/gear-finder-003.test.js\`: фактический каталог и нулевые источники для несуществующего материала, порядок/стоимости миссий, первая бесплатная победа и блокировки, 1★-повтор и 3★-симуляция, расчёт отдельного слота, суммирование шести предметов без двойного списания, все пять временных классов до G13, неисправные профили, неизменность исходного состояния. Через штатный \`npm test\` также проходят старые сценарии боя, сохранения и UI.

Отдельно: CI браузеров подтверждает отсутствие регрессий **текущей** игры; новую визуальную цепочку «Найти» в браузере пока проверять нечего. На iPhone Safari ассистентом этот этап не проверялся.
