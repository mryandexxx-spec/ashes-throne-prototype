# GEAR-G13 — расширение снаряжения G1–G13

**Статус: [В РАЗРАБОТКЕ] — единый функциональный PR GEAR013; числовой баланс и названия новых предметов [ПРЕДЛОЖЕНИЕ].**
**Основание:** запрос владельца 13.11.2026, GDD 3.0 §11, AI_WORKFLOW, существующие GearData / ProgressCore / ProgressV3Core. Этот документ не утверждает новые цены, классы предметов, названия или формулы и не означает, что G4–G13 уже реализованы.

## 1. Цель и неизменные решения
- Шесть независимых слотов на каждом из рангов G1–G13, последовательное заполнение и отдельное подтверждение повышения ранга.
- Каждая устанавливаемая вещь даёт **собственный, видимый и действительный** бонус, а не только декоративное название. Итоговая прибавка в карточке и бою рассчитывается из установленных вещей.
- Данные каждого персонажа независимы; история предыдущих рангов сохраняется при повышении. Не уничтожать текущие G1–G3, ресурсы, уровни, звёзды и навыки, в том числе CHAR003.
- G13 является конечным рангом этой задачи. Последующее усиление после G13 — отдельная система, не разрабатывать скрыто в этом PR.
- Приоритет iPhone Safari landscape, без лишних 3D-ассетов, сетевых зависимостей и горизонтального скролла.

## 2. Что уже есть в main (на начало этапа)
- `gear-data.js`: каталог только G1/G2/G3, шесть слотов, класс-ограниченные предметы, рецепты из семи материалов, тестовые бонусы HP/ATK.
- `progress-core.js`: цена установки, покупка, повышение G1→G2→G3, сохранение истории установок и агрегирование HP/ATK; ряд заглушек v2 сохраняется для старых тестов.
- `progress-v3-core.js`: `validateActive` допускает только ранги 1,2,3. v3 профиль хранит `heroes[id].gear.{tier,installedByTier}`; runtime — `gear[id].{tier,slots,history}`.
- `hero-stats-core.js` и `hero-stats-combat-bridge.js`: для Рена, Нады, Лиоры есть 14-статная модель, но предметные бонусы пока поступают как HP/ATK проценты; обычная экипировка **не добавляет скорость**.
- `game.js`: слот, предложение предмета, покупка и отдельное повышение ранга связаны с интерфейсом досье.
- Экономика, рецепты и показатели G1–G3 — тестовые. Нельзя представлять их каноном мира или утверждённым балансом.

## 3. Предлагаемый контракт предмета [ПРЕДЛОЖЕНИЕ]
```js
{
  id: "g4-...", tier: 4, slotId: "weapon",
  allowedClasses: ["melee"], name: "...",
  ingredients: { Fe: 1 }, currency: 100,
  bonuses: { physicalAttack: 5, critChance: 1 }
}
```
- `bonuses` содержит только разрешённые ключи из `HeroStatsCore.KEYS`. Количество и проценты должны быть явно нормированы: фиксированные пункты / абсолютные показатели либо отдельный контракт множителей, **без смешения единиц**.
- Для первых 3 рангов оставить существующую семантику процентов HP/ATK и мигрировать расчёт только после теста эквивалентности. Не меняем исторические бонусы задним числом.
- Бонусы должны различаться хотя бы по роли/слоту и выполнять заявленную функцию. Не предлагать игроку два предмета с одинаковыми характеристиками, если их выбор ничем не отличается.
- Скорость остаётся неизменной от обычной экипировки в соответствии с нынешними правилами характеристик. Её отдельное изменение требует согласования.
- Для демонстрационных героев, ещё не переведённых на 14 статов, либо явно ограничить предлагаемые эффекты поддерживаемыми характеристиками, либо предварительно провести отдельную миграцию профиля; не терять бонус молча.

## 4. Границы реализации — четыре составляющие ОДНОГО функционального PR

### GEAR013-A — модель и совместимость сохранения
- Расширить поддерживаемые ранги до 13 **без записи нового значения до появления соответствующих предметов**.
- Ввести единый источник `MAX_GEAR_TIER = 13` для catalog/runtime/validator и проверок.
- Валидатор v3: каждый исторический ранг существует без пропусков и полностью заполнен; текущий содержит шесть позиций с `null` либо допустимыми item IDs; предмет соответствует рангу, слоту и классу.
- Сохранить существующий формат v3, если он достаточен. Если потребуется миграция, она должна быть явной и без потери исходника.
- Тесты: старый G1/G2/G3 профиль → чтение/запись без изменения; повреждённые данные → отказ от перезаписи; запрет чужих ID; конкурирующие вкладки/revision; сохранение CHAR003 `passiveLevels`.

### GEAR013-B — каталог и экономика G4–G13
- Добавить полную матрицу шести слотов на каждый ранг и необходимые варианты по существующим тестовым классам.
- Рецепты, цены и условия доступа — маркировать [ПРЕДЛОЖЕНИЕ]. Проверять достижимость ресурсов через существующие миссии и инструменты тестирования; не добавлять бесконечные награды в обычный игровой цикл.
- Промоушен требует 6 установок, отдельного подтверждения и доступных ресурсов; G13 запрещает повышение.
- Тесты на последовательное прохождение G1–G13 для Рена/Нады/Лиоры и каждого поддерживаемого класса; нельзя установить в чужой слот, купить дважды, уйти в минус или пропустить ранг.

### GEAR013-C — индивидуальные характеристики и бой
- Проводить бонус каждой вещи через единую функцию расчёта характеристик, а не отдельно через текст интерфейса.
- Обеспечить однократный учёт каждой установленной вещи, включая историю предыдущих G.
- Не нарушать допустимые пределы 14-статного resolver; проверить процентные / абсолютные единицы и округления.
- Тесты сравнения характеристик до/после покупки и после перезагрузки: HP, атака, защита, крит, точность и т.п. Проверить реальные удары, защиту/эффекты, победу/поражение, автобой, повтор, изоляцию бонусов между героями.
- Сохранить заявленное правило «обычная экипировка не повышает скорость», пока владелец не изменит его.

### GEAR013-D — интерфейс и приёмка
- Сохранить акцент на большой 3D-модели героя в принятой карточке; шесть слотов, текущий G, требования, ресурсы, предпросмотр `до → после`, недоступные действия и причины блокировки.
- Визуальный язык `UI_DESIGN_SYSTEM.md`; для длинного списка предметов прокрутка **внутри** диалога/панели, не всей страницы.
- Футер и `package.json`: одинаковая новая версия и уникальный код этапа у каждого игрового PR.
- Сценарии браузерной регрессии: пустой профиль, старый G3, частичный G4, новый G13, критический недостаток валюты, возврат, повторный запуск, восстановление после перезагрузки.
- Safari landscape: футер сборки (проверить **первым**), safe-area, короткая высота, touch, keyboard/Escape, скрытие/появление панели, отсутствие горизонтального переполнения.

## 5. Главные риски
1. **Потеря прогресса:** существующий валидатор прямо запрещает G4+; выпуск интерфейса или каталога раньше валидатора может сделать профиль нечитаемым.
2. **Двойной учёт бонусов:** сейчас G1–G3 добавляют проценты HP/ATK и отдельные бонусы повышения; новая модель 14 статов не должна применять старое и новое одновременно.
3. **Ложная индивидуальность:** десятки названий с одним `hp/atk` бонусом формально расширят каталог, но не улучшат игру.
4. **Недостижимость G13:** нынешние ограничения героев, валюты и миссий разработаны для G3. Доступность каждого шага нужно проверять, но экономику не объявлять утверждённой.
5. **Мобильный UX:** 13 рангов × 6 предметов нельзя отобразить одной большой таблицей на коротком landscape.
6. **Отложенная приёмка CHAR003:** существующий `main` используется как основа; после изменений сохранять работу `passiveLevels`, отдельно фиксировать, что пользователь пока не принимал CHAR003 на физическом iPhone.

## 6. Условия полного завершения
- Реально устанавливаются шесть вещей на каждом G1–G13 и повышается ранг от G1 до G13.
- Каждая вещь изменяет поддерживаемые боевые характеристики и игрок видит эффект до покупки.
- Любая завершённая ступень сохраняется между сессиями без отката; старые v3 сохраняются.
- Тесты экономических отказов, героев, валидатора, боевой регрессии и мобильного интерфейса проходят.
- GitHub Actions и браузерные проверки задокументированы отдельно от теста физического iPhone.
- Вся система предъявляется владельцу одним функциональным PR. **Без разрешения владельца не сливать.**
