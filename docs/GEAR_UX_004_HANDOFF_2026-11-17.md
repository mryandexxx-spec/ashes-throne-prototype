## Что уже существует
- 6 фиксированных слотов, классовые шаблоны G1–G13, 7 материалов; покупка одновременно изготавливает и устанавливает предмет; сохранение v3.
- Независимый Finder рассчитывает `GearPlanningCore.plan(progress,heroId,slotId,campaign)`, `planTier(progress,heroId,campaign)`, `findSources(materialId,progress,campaign)`; источники выводятся из реальных `MissionData`, `CampaignData` и `ProgressCore.MISSION_GEAR_FARM`, а не из параллельного каталога.
- `GearSourceData.findSources(materialId,campaign,energy)` различает закрытую миссию, первый бесплатный вход с наградой при победе, 1★ ручной повтор и 3★ симуляцию. Все API **не подключены** к DOM; сама UI-цепочка «Где взять» ещё не работает.
- Игровая версия остаётся `v0.3.181 · GEARSAFE002`: GEAR-FINDER — кодовая библиотека без изменения пользовательской сборки.
- Для будущего UI прежде всего актуальны: конфликт модального окна и крупной 3D-модели, чтение рецепта, дефицит, один короткий путь до источника, сохранение героя/слота при возвращении, доступные тапы, отсутствие скролла страницы в landscape.

**Получить отдельное утверждение владельца на UI, до этого не создавать UI-код PR.** После утверждения — создать отдельную рабочую ветку и точечный PR GEAR-UX-004; подключить существующие чистые модули в правильном порядке и связать с реальным `campaignProgress`/сохранением; не вводить новые награды, уровневые гейты, случайные дропы, сервер или инвентарь.
