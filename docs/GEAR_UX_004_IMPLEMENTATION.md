# GEAR-UX-004 — контекстное досье экипировки (вариант B)

**Дата:** 17.11.2026.
**Дизайн:** [УТВЕРЖДЕНО владельцем] в диалоге после сравнения 3 вариантов и визуального концепта.
**Код:** [В РАЗРАБОТКЕ / отдельный PR]; **не считать реализованным в main до слияния и проверки**.

## Область работ

- Вместо перекрывающего главного героя gear-dialog при нажатии на слот открыть две боковые панели досье. **Центральная 3D-сцена и все 6 кликабельных слотов не пересоздаются.**
- Слева — реальное имя предмета, слот/G и бонусы из \`GearData\`; «до → после» в первой реализации — фактический суммарный процентный бонус экипировки HP/ATK, **не** спекулятивное вычисление всей 14-статной формулы. Остальные бонусы показываются как прототипные.
- Справа — точные материалы \`есть / нужно / не хватает\`, игровая валюта, единственная кнопка изготовления с тем же \`ProgressCore.equipItem\` / \`persistProgress\`; при 6/6 отдельный существующий переход G, G13 — максимум. Нельзя обойти \`saveBlocked\`.
- «Найти» → материал → все реальные источники \`GearPlanningCore.findSources\` → разрешённый ручной бой или 3★-симуляция. 1★/2★ — только ручной повтор; закрытая миссия показывает условие; первый вход бесплатен; при недостатке энергии кнопка неактивна. Никаких новых источников и шансов.
- Ручной бой: запомнить в оперативной памяти \`{heroId,slotIndex,missionId}\` до открытия отряда. **Назад из отряда**, **К предмету в результате боя** возвращают на того же героя/слот с новым пересчётом дефицита. Результат → «Повторить» сохраняет контекст; «Домой» сбрасывает. Симуляция открывает существующий диалог и после результата обновляет досье.
- Сохранение v3, правила кампании, покупка/переход, ресурсы, расчёт 3D, награды, модели и баланс не меняются.

## Компоновка и доступность

- Landscape в первую очередь 844×390 и 932×430; верхний HUD текущего досье остаётся, колонки примерно 24% / оставшаяся ширина / 24%.
- Без скролла всей страницы: прокручивается только содержимое левой/правой панели, \`overflow-x:hidden\`; модель остаётся визуально главной.
- Кнопки 44px по высоте, \`focus-visible\`, закрытие по Escape (в источниках сначала возвращает в предмет), диалоги сохраняют собственный Escape, уважать \`prefers-reduced-motion\`.
- Никакого нового WebGL, фоновой перезагрузки модели или серверных зависимостей.

## Проверить перед слиянием

1. На чистом v3: герой → пустой слот → предмет → дефицит → «Найти» за ≤3 действия. Рен и шесть слотов остаются видимыми.
2. Статусы \`locked\`, \`unknown\`, \`first-clear\`, \`repeat\` 1★/3★, недостаток энергии; отсутствие лишних кнопок.
3. Пройти бой; победа и поражение → «К предмету»; отступить из отряда → прежний герой/слот; повтор миссии; симуляция → результат → обратно к рецепту.
4. Изготовление одного предмета без двойного списания; 5/6 и 6/6; повышение G; G13; ошибка сохранения; 0 валюты.
5. Размеры 844×390 и 932×430, safe-area и URL-bar iOS; отсутствует горизонтальный скролл; фокус/клавиатура/Escape; отсутствие повторной 3D-сцены.
6. Node CI и browser Chromium/WebKit; после опубликования — физический iPhone Safari и термонагрузка отдельно, без фиктивного утверждения тестирования.

## Ограничение

GEAR-UX-004 решает навигацию поверх текущих **демонстрационных** миссий. Экономическая достижимость без dev-ресурсов, итоговые rewards и баланс G4–G13 остаются предметом **GEAR-ECON-005 / GEAR-FARM-006**, не утверждаются этой UI-задачей.
