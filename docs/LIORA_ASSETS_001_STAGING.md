# LIORA-ASSETS-001 — размещение GLB Лиоры и щита

**Статус:** [В РАЗРАБОТКЕ]. Подготовлен пакет поставки в структуре проекта; бинарники в GitHub ещё не перенесены.

## Источник архитектуры
Актуальный `main`, `docs/NADA_3D_001_INTEGRATION.md`, `dev/assets/models/manifest.json`, `dev/src/assets/models.js`, `dev/assets-src/characters/nada/README.md`, `docs/CHARACTER_ONBOARDING.md`. Рен всё ещё имеет старую схему `assets/ren-meshy-mixamo-animated.glb`; у Нады уже принята структура `dev/assets/models/`. Следовать новому образцу Нады без перестройки Рена.

## Планируемый пакет
- `dev/assets/models/liora-mobile-animated.glb` — отдельный скиннингованный герой, 2 777 056 байт.
- `dev/assets/models/liora-shield-mobile.glb` — независимый щит, 631 488 байт.
- `dev/assets/models/manifest.json` — существующая запись Нады + новые записи Лиоры и щита (записать одновременно с бинарниками).
- `dev/src/assets/models.js` — сохранить `NadaModelAssets` без изменений, добавить `LioraModelAssets` и `LioraShieldAssets` только вместе с файлами.
- `dev/assets-src/characters/liora/README.md` — происхождение, технические показатели, этапность. Не копировать исходные 8,46 и 3,88 МБ в публично обслуживаемые игровые каталоги.

## Вывод по последовательности
**Сначала разложить два оптимизированных GLB и зарегистрировать пути, потом привязать щит в Babylon.** Связывание — операция на сцене: import щита → поиск кости левой руки → корректный локальный трансформ → родительская привязка → воспроизведение каждого клипа. Не запекать щит в GLB персонажа до проверки посадки и анимаций.

## Стоп-условия
- В этом PR **нет бинарников**, и он **не должен сливаться** как «внедрённый ассет».
- Никаких изменений в runtime, кэше моделей, сборке, досье и коллекции героя пока нет.
- Перед слиянием: проверить полный пакет, хеши, доступность URL и отсутствие регрессий в браузере; физический iPhone отдельно.
- Привязка щита, поведение игровых умений и постоянное открытие Лиоры — самостоятельные задачи.
