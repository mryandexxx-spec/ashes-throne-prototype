# LIORAPLAY001 — Лиора без щита в ростере, карточке, бою и кеше

**Статус: [В РАЗРАБОТКЕ] — черновой PR #299, не слит.** Решение владельца от 13 ноября 2026: внедрить Лиору без щита по образцу Рена/Нады, добавить кеширование. Все числовые значения и игровые действия Лиоры — **тестовый пилот, не утверждённые класс, баланс или литературный канон**.

## Состав изменений
- `game.js`: Лиора (`liora`) — отдельный постоянный ID, временная стартовая доступность, 3D карточка и условная загрузка GLB в действующую арену только когда герой в отряде. Бои без Лиоры обходятся без её GPU-объектов.
- `liora-glb-runtime.js`: 66-костный анимированный GLB `dev/assets/models/liora_vel_shield_aware_15clips.glb` (2 850 224 байта), тот же один Babylon Engine, что у арены. Контрольный набор клипов без обращения к щиту: ожидание `Idle_02`, базовый удар `Step_Forward_and_Push`, особая способность `Squat_Stance`, получение урона `Hit_Reaction`, смерть `Dead`. При ошибке загрузки видим старый схематичный манекен; при выходе из боя/перестановке героя объекты очищаются.
- `ren-card-3d.js`: модель Лиоры загружается и вращается в штатной карточке; без придуманного портрета, с текстовым fallback. Визуальный GLB используется повторно через browser cache, но card и battle хранят отдельные WebGL Scene, как у Рена/Нады.
- `model-cache-sw.js` и `model-cache-client.js`: whitelist из трёх GLB (Рен 2 862 860, Нада 1 462 284, Лиора 2 850 224 байта). Отдельный новый кеш-ключ `liora-a2cc310c` и перенос неизменённых кешей Рена/Нады без скачивания. Не кешируются HTML, JS, сохранения, щит и запросы с range/query. Фоновая подготовка отключается при экономии трафика, медленной/сотовой сети и в скрытой вкладке.
- `hero-collection-core.js`, `star-core.js`, `skill-core.js`, `progress-v3-core.js`: добавлен ID в согласованные схемы. Старые сохранения с 5, 6 и 7 героями расширяются только по историческим наборам с точной резервной копией `.before-liora`. Уровни, валюты, навыки и инвентарь не перезаписываются. Повреждённые сохранения блокируются, а не стираются. PROG085 и последующий RENRETREAT001 из актуального `main` сохраняются.
- `hero-stats-*.js`, `ability-data.js`, `hero-profile-data.js`: тестовые 14 параметров и учебные способности без щита, без выдуманной биографии.
- Тесты: старые исторические пятёрки остаются фиксированными для сравнений; новые сценарии отдельно проверяют восьмого героя. Chromium и WebKit должны подтвердить реальную 3D карточку и активный бой, CacheStorage/offline — три модели.

## Принципиальные ограничения
1. **Щит отключён полностью**. GLB и устаревшие скрипты крепления оставлены в репозитории как архив исследования, в игровом runtime не используются. Названия `Shield_*` внутри исходного GLB не означают, что щит добавлен.
2. Тестовые класс `tank`, способности `guard`, цифры и стартовый доступ — **[ПРЕДЛОЖЕНИЕ]**, не новый канон и не окончательное решение по получению героя.
3. Требуется проверить пользовательские сценарии на физическом iPhone Safari: карточка → бой → смерть/победа → повтор → карточка, FPS/нагрев, поворот/закрытие Safari, кеш и офлайн-повтор.
4. Не сливать PR #299 без отдельного разрешения владельца. Не называть опубликованным до успешной проверки `main` и Pages.
