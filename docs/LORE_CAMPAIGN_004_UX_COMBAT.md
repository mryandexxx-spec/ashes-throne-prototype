## Решение UX — чтение без прокрутки всей страницы

Проблема предыдущей пробы: сцена была одним вертикальным столбцом, рядом с текстом появлялись осмотры и задачи, доступ к кнопкам требовал постоянной прокрутки в iPhone landscape.

Решение:

- **Полноэкранный игровой режим диалога** при landscape с высотой до 540 CSS px. Контент фиксирован относительно viewport (`position:fixed`, `100dvh`, учёт четырёх `safe-area-inset`), общий `body` без прокрутки. По выходу восстанавливается обычный режим.
- **Левая половина:** портрет говорящего, имя, одна смысловая страница текста, навигация «‹ / ›» и счётчик страниц. Длинный текст дробится *только на уровне отображения* и **не меняет** авторский сценарий, состояние `beat` или сохранение. Действия продолжения отображаются только на последней странице.
- **Правая половина:** осмотр / сопоставление с раскрытием информации, компактная раскрываемая сводка целей, фиксированные относительно панели кнопки выбора и продолжения. При избытке предметов прокручивается *только узкая область осмотра*, не вся страница. Все значимые кнопки около 44–48 CSS px.
- **Портреты из уже существующих игровых ассетов:** `assets/ren-portrait-ui.webp`, `assets/nada-portrait-ui.webp`, при необходимости `assets/liora-portrait-ui.webp`. Для нейтрального повествования вместо выдуманного лица — фрагмент обложки хроники. ID говорящего берётся из сценарного пакета, путь к картинке — **из фиксированного разрешённого списка**, не из непроверенного текста. Портреты не грузят 3D и не дублируют большие GLB.
- В портретной ориентации остаётся привычная последовательная вёрстка с прокруткой, без искусственного масштабирования горизонтального дизайна.

## Игровой бой без ложного канона

В принятой главе 1.3.1 Рен и Нада никого не атакуют; превращать безоружный сюжетный переход в обязательную схватку было бы нарушением последовательности.

В игровом PR добавлена **отдельная, добровольная тактическая тренировка**:

1. На **верхней строке карты «Пяти теней»** всегда видна кнопка «⚔ Тактический бой · Вне канона · без энергии»; не нужно прокручивать карту до конца.
2. Игрок входит в **существующий экран выбора отряда**, выбирает доступных героев (сейчас в пилоте могут быть и учебные герои).
3. Запускается **настоящая 3D-арена**, существующий `CombatCore`, вручную доступные способности, автобой, скорость, обычные боевые анимации. Враги — переименованные **копии уже существующих учебных шаблонов**, не новые персонажи мира.
4. Результат победы/поражения показывается на отдельном экране; доступны **«К карте» / «Ещё бой» / «В штаб»**. Выход во время боя через верхнюю кнопку возвращает к лорной карте, а не выбрасывает в главный хаб.
5. **Никаких затрат энергии, материалов, наград, осколков, звезд, выдачи героев или сюжетной разблокировки по результату тренировки.** Профиль `progress.v3`, обычная кампания и `ashes-throne.lore-campaign.v1` не изменяются. Выбор игрового состава подчиняется обычному сохранению состава отряда, но не награждает игрока.
6. GPU-рендеринг останавливается при выходе из боевого экрана по действующему механизму `showScreen`.

**Это полноценная боевая механика внутри раздела истории, но НЕ утверждённый сюжетный бой.** Позже владелец может отдельно одобрить альтернативную **игровую интерпретацию** с боевыми миссиями, их последствиями и наградами. До такого решения лорные узлы не запираются за неканоничным противником.

## Изменения в коде

- `lore-campaign-ui.js` — портреты, пагинация, фиксированные зоны сцены и компактный вход в тренировку на карте.
- `lore-campaign.css` — короткий landscape, safe-area, портреты, меню действий, кнопка боя и результат.
- `game.js` — флаг `battleIsLoreTraining`, вызов **той же 3D-арены**, возврат после завершения/отмены, без пути наград.
- `index.html` — отдельный экран результата тренировки.
- `tests/lore-campaign-landscape-training.test.js`, `tests/lore-campaign-training-browser.cjs`, `.github/workflows/lore-campaign-training-browser.yml` — UI и полный сценарий боя.
- Приватный PR #63 — генераторы автономного HTML и **закрытой полной сборки игры**, где реальные сценарные данные FS-01–FS-03 встраиваются **только во временную копию** игрового кода. Никаких закрытых реплик в публичном игровом PR.

## Критерии проверки

- [ ] Node тесты всех режимов и статические инварианты без регрессий.
- [ ] Chromium/WebKit 844×390 и 932×430 — портрет, страницы текста, фиксированная вёрстка, обязательный осмотр, выход/возврат, отсутствие переполнения.
- [ ] Chromium/WebKit **реальный Babylon WebGL**: хаб → карта → состав → бой → победа или поражение → результат → повтор/выход → карта; неизменность кошелька, обычной кампании и лорного прогресса.
- [ ] Закрытая игровая сборка [PR #63](https://github.com/mryandexxx-spec/ashes-throne-worldbuilding/pull/63) действительно содержит три сценических узла + бой; опубликованная сборка `main` пока не содержит новых текстов.
- [ ] **Реальный физический iPhone Safari**, safe-area и жесты прокрутки — обязательно проверить после авторского утверждения и разрешённого слияния; браузер WebKit CI не заменяет устройство.

## Авторский следующий шаг

Не выдавать условное столкновение за случившееся в главе 1.3.1.
