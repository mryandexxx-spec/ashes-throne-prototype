## 1. Миссия исполнителя

Реализовывать **только следующий утверждённый этап** `docs/LORE_CAMPAIGN_ROADMAP_0.1.md`; не перескакивать к эффектным экранам, наградам, новым сражениям и сюжету без устойчивого основания. Принцип: **один ограниченный этап → код и тесты → PR → явное разрешение на merge → проверка обновлённого main → следующий этап**.

Владелец утверждает авторские решения. AI самостоятельно делает доступную техническую работу и проверяет результат; не просит владельца писать программный код и не задаёт многократные вопросы по уже согласованному.

## 3. Жёсткие запреты

- Не изменять принятый рассказ, `WORLD_STATUS.md`, `CURRENT.md` или GDD только ради приспособления под механику. Новые события и диалоги — **[ПРЕДЛОЖЕНИЕ]** до художественной приёмки.
- Не делать из романного конфликта безусловный бой, не создавать разбойников/монстров «для геймплея» и не объявлять сюжетную пробу `Дорога, которой нет` каноном. Не утверждать вступление Рена/Нады/Лиоры в организацию без сценарного основания.
- Не обнародовать в публичном игровом репозитории **весь приватный сценарный документ** или полную подборку спойлеров. Игровые строки, которые должны видеть пользователи, публиковать только после отдельного сценарного согласования и проверки момента раскрытия.
- Не включать неутверждённую валюту, шансы выпадения, энергию, награды, цены, дневные лимиты; **не осуществлять начисление через нулевую «заглушку»**.
- Не смешивать `ashes-throne.lore-campaign.v1` с `ashes-throne.campaign.v1` и `progress.v3` на раннем этапе; миграцию кошелька разрешать только отдельной экономической задачей.
- Не заменять Babylon.js, не писать новый боевой движок, не подключать сервер/новый фреймворк, не создавать постоянную WebGL-сцену ради 2D-карты.
- Не сливать PR без явного разрешения владельца **на конкретный показанный PR**. «Ок» в ответ на общую идею не является разрешением слить любой PR.
- Не менять чужие открытые ветки и PR без необходимости; не считать старый handoff актуальным снимком `main`.
- Не заявлять браузерную/мобильную проверку, если сделан только синтаксический/Node-тест. Не заявлять публикацию до сверки GitHub Pages.

## 4. Стандарт исполнительской задачи LC-00N

В начале рабочего документа/PR зафиксировать:

| Поле | Требуемое значение |
|---|---|
| Этап | `LC-00N` и точная строка дорожной карты |
| Статус | [ПРЕДЛОЖЕНИЕ] / [В РАЗРАБОТКЕ] / [РЕАЛИЗОВАНО] с уровнем проверки |
| Источники | текущие SHA обоих `main`, релевантный GDD, авторская часть |
| Цель | одно проверяемое поведение пользователя |
| Изменять | точный ограниченный перечень файлов |
| Не изменять | список соседних экранов, логики, сохранений и художественных фактов |
| Состояния | основной проход, повтор, заблокировано, ошибка, возврат |
| Acceptance | 4–10 проверяемых условий и хотя бы один отрицательный сценарий |
| Проверки | Node, Chromium, WebKit, производительность, физический iPhone — каждый отдельно |
| Итог | URL PR, файлы, проходящие/непроходящие проверки, риски, следующий шаг |

Подготавливать маленькую ветку от **фактического актуального `main`**, а не от старой рабочей ветки; если требуется зависимый стек PR, показать владельцу цепочку и не объявлять последний PR готовым к слиянию раньше базового.

Каждый кодовый PR, изменяющий опубликованную игру, обновляет одновременно `package.json` и футер `#buildVersion` в `index.html`, с согласованным новым кодом этапа; при этом не следует поднимать версию для **только документационных** PR.

## 5. Технические приоритеты по порядку

**LC-000 — авторский выбор.** Получить согласование формата «интерактивная хроника», границ изменения литературных событий, пилота FS-01–FS-03 и решения, возможны ли условные бои. Пока выбора нет — не делать канонические сюжетные реплики и не включать бой.

**LC-001 — модель.** Чистые данные/валидатор. Сначала тесты ID, ссылок, DAG, доступности и reward-null; потом код. Никакого UI, новой энергии или баланса.

**LC-002 — карта.** Реально работающая навигация в `#campaignLoreContent`. Проверить тап каждого маркера, назад, фокус, 844×390 / 932×430, safe-area. Никаких GLB ради карты.

**LC-003 — история.** Тестируемый исполнитель кадров/выборов и отдельное версионированное сохранение. Основные решения **write-once**; повтор может показывать альтернативы, но не меняет журнал/первичный маршрут. Порча локального ключа не должна удалять сохранения коллекции.

**LC-004 — первая часть.** Разработать и согласовать сами сокращённые сцены и реплики. Проверить отдельно таблицу знаний Рена/Нады/читателя и причинность. Игрок должен не только читать, но выполнить осмотр, сравнение и содержательный выбор.

**LC-005 — разные действия.** Ввести максимум необходимые переиспользуемые задачи (наблюдение, сравнение, выбор). Не делать новую систему морали, сложную RPG и длинное дерево сюжетных ветвей.

**LC-006 — бой и контракт фарма.** Только после сценарного разрешения на конкретное условное испытание. Различать ручной повтор, автобой, симуляцию ×N и мгновенно ×1. **При `rewardPoolId:null` и `energyCostId:null` нельзя платить/получать ничего**; не рисовать доступную кнопку симуляции без реального пути получения 3★.

**LC-007 — остальные части.** Переносить небольшими утверждаемыми пакетами, сверяя часть за частью и не перескакивая по источнику знаний. Чужой литературный тезис не становится объективной механикой.

**LC-008 — экономика.** Отложена до прямого решения владельца. Только здесь проектировать источники наград, списания, квитанции/idempotency, миграции и реальную симуляцию/мгновенную выдачу. Никаких чисел заранее.

**LC-009 — QA и публикация.** Полный сценарий, отсутствие лагов/неверных карт/дублей слушателей, сохранность профиля, CI, WebKit, затем физический iPhone владельца, Гитхаб Pages и фиксация статуса.

## 6. Правила перехода от этапа к этапу

1. Считать этап завершённым, когда **его заявленное поведение** реально проверено, а не когда файлы просто написаны.
2. Проверить CI после последнего коммита, не ссылаться на тесты предыдущего SHA.
3. Показать владельцу PR, риски и проверенный результат; получить **прямое разрешение на merge**.
4. После разрешённого слияния проверить `main` и страницу публикации; только потом менять текущий статус LC на завершённый.
5. После принятого этапа обновить `docs/PROJECT_STATUS.md` и при необходимости `CHANGELOG.md`/дорожную карту; не превращать статус в длинную историю.
6. Если P0/P1 регрессия, остановить расширение, сделать минимальный исправляющий PR, проверить восстановленный сценарий.
7. Если литературная неопределённость — оставить соответствующий узел/сцену как [ПРЕДЛОЖЕНИЕ] и не блокировать остальные технические тесты, не сочиняя отсутствующий факт.
8. При конкурирующих предложениях сравнить варианты, указать лучший и почему, но не менять уже утверждённый принцип самостоятельно.

## 7. Набор обязательных регрессионных проверок

**Логика графа:** путь к финалу, отсутствие циклов и зависшего закрытого узла, независимость optional-ветви, запрет неизвестного/закрытого ID, корректный граф при добавлении второй истории.

**История:** верный speaker/source knowledge, осмысленная развилка, запоминание первого решения, альтернативный replay без изменения оригинала, отсутствие спойлера раньше узла, можно пропустить просмотренный текст, но нельзя перескочить обязательный выбор.

**Сохранение:** обычный профиль, профиль до новой кампании, новая сессия, старый/частично повреждённый ключ, недоступный localStorage, один и тот же узел 2+ раза, отсутствие начислений при незаданной политике.

**Экономический контракт:** симуляция только после заслуженного условия 3★ (для боя); `count` проверяется, будущие операции идемпотентны и проверяют доступность ресурсов; уникальная награда первого прохождения не повторяется; пока награды TBD, нет списания, начисления и фиктивного успеха.

**Навигация:** хаб → лор → карта → узел → действие → результат → карта, возврат в штаб и обратно; бой/поражение/повтор/выход без двойного зачёта, если соответствующий тип узла реализован.

**Мобильность/перфоманс:** landscape с короткой высотой, safe-area, touch target около 44px, отсутствие горизонтального скролла, возврат из фонового Safari, повторные открытия без растущих слушателей/рендер-циклов, отсутствие предварительной загрузки тяжелых GLB на карте.

**Регрессия старой игры:** учебная кампания, прежние звёзды, награды, симуляция, три миссии, бой/поражение/перезапуск, карточка героя и ростер, локальные профили и отдельная неканоническая сюжетная проба.

## 8. Обязательный отчёт пользователю после каждого PR

Писать кратко и по существу:
- **Что готово:** конкретный сценарий/механика с точным статусом.
- **Что изменено:** имена файлов и ссылка на PR.
- **Проверки:** числа Node-тестов и реальные браузеры, iPhone отдельно (либо «не проверен»).
- **Риски:** данные, литературный канон, производительность/ресурсы, открытые ограничения.
- **Следующий шаг:** точный номер LC, зависит ли от решения владельца.
- **GitHub:** явно «PR открыт, не слит» до согласия; после слияния отдельно проверить опубликованный `main`.

Не доказывать готовность скриншотом заглушки: по каждой видимой кнопке проверять реальный обработчик, изменение состояния и повторное использование.
