27.11.2026 · [ПРЕДЛОЖЕНИЕ] Рабочая декомпозиция утверждённого направления MAP_3D_PLAN.md. Не новый GDD, канон или баланс. Измерения и ограничения в MAP_3D_01_RESEARCH.md.
## Решение
Babylon.js 9.33.2 + Recast 0.43.1 как основной технический кандидат, Navcat 0.4.1 резерв. Оба 9/9 Node, 54/54 браузер, Recast быстрее в трёх запусках; авторский граф 8/9 и ограничен заранее заданными точками. Не строить собственный универсальный решатель. Не внедрять crowd, Havok, новый framework, сервер или редактор сейчас. Recast напрямую проверен, Babylon Navigation V2 использует тот же решатель; интеграцию через плагин рассматривать только если уменьшает код/риски. Existing Ren GLB has Walking/Running/Idle_4; test them first. CharacterController/T5C are references not adopted dependencies: no evidence they solve our animation ownership/scene lifecycle better. Blender 4.5.17 + script export verified; Babylon Editor optional later. No new runtime packages in 01.
## Контракт уровня (рабочий)
- Source .blend with ART/NAV/MARKERS, visual GLB, nav source + prebaked binary, versioned manifest and stable event IDs. RH Y-up meters; test transforms, orientation, marker reachability and actual collision proxies. Decorative geometry separate from navigation; significant obstacles must be represented in NAV, no clipping. Spawn/exit/event IDs are semantic; changing art or position must not invalidate saved progress. Source and build recipe versioned, artifact hashes/provenance recorded. No published raw third-party asset without distribution permission. Offline bake primary, verify nav binary compatibility/version and integrity, fail gracefully on mismatch.
- One screen owner, disposable engine/scene as existing runtime permits; async import cancellation tokens, teardown and resource ownership explicit. One transform owner for hero movement; single animation controller idle/walk/run with transition, orient on path tangent, remove double root motion; route validation rejects incomplete results and excessive snapping. Never trust raw success flag. Camera follow with damping, zoom range, screen readability, occlusion handling; pinch/drag cannot issue a move; tap target while camera moving must be precise. Test resize/safe area, background/foreground, slow asset load, interrupted scene.
- Separate view, nav adapter, level metadata, interaction/state coordinator; no second reward system. Existing MainCampaignCore and save/receipt rules authoritative. Screen opening/handoff uses actual mission ID, not arbitrary 3D object name. On reload restore valid location or safe checkpoint; if invalid data, safe return. Battle victory/defeat/retreat/retry via actual game rules and proof; return to prior valid point and never duplicate rewards. Define schema only after reviewing latest SaveCore and campaign flow at 06; no independent browser storage. 
## Игровой цикл и UX (proposals for tests)
Enter compact region -> see next objective and optional opportunity -> tap destination -> hero moves along walkable route -> discover/interact -> preview encounter and choose existing battle -> return -> next choice. Movement is not combat; no joystick or long obligatory traversal. Keep UI lightweight, no full screen scroll, overlay details only when needed. Main objective identifiable without text-heavy tutorial. Landscape safe areas; hero/targets visible even at min zoom. No automatic battle from accidental tap. If invalid destination, give feedback and compare keep-current-route vs stop behavior; not approved UX. Tap on already completed encounter offers existing repeat rules where applicable, do not add sweeping rewards/energy rules. Optional backtracking shortcut only if compatible with approved mission progression.
Prototype branching: short direct path to required encounter, alternative route with visible optional point of interest, a second side discovery, reconnection. No choice should permanently lock required chapter progression unless approved explicitly. Do not copy roguelite boons/risks from Hunting Grounds into campaign. No new rewards, enemies, lore, fog rules, consumables, resource values approved here. Use neutral IDs and test labels for 02, actual chapter content only after canon review in 05–07. Existing chapters and FirstPlay retained.
