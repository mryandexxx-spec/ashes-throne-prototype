## 02A design and critique
Combine the proven exported level and existing Ren with the proven input/camera principles, rather than extend the procedural capsule demo. Offline Recast binary plus hash manifest and matching geometry. Use independent geometry for picking and grounding; never infer ground height from x coordinate. The visual GLB is separate from movement. Only one owner for motion, animation groups are switched on state change. Neutral marker interactions show arrival only; no battle, rewards, saves or lore. Avoid adding framework/editor/physics, no production dependency. 
Alternatives: direct click on visual GLB risks decorative occlusion and artist changes; use authored nav proxy instead. Runtime bake adds unnecessary loading and variance; use serialized Recast. A waypoint-only map contradicts approved walkable world. A capsule-only repeat would prove little; use actual Ren. Do not mask animation defects with procedural proxy. Lab UI deliberately minimal and clearly labeled, not final game UI. 
Test real screen taps in Chromium and WebKit, arrival through both branches and ramp, invalid point rejection, changing destination during movement, stop/idle, reload, repeat entry/exit. Render actual hero and imported floor; inspect captures/video separately. Native locomotion root translation may require filtering; remove only identified horizontal root translation, not arbitrary joint motion; no gait claim before review. No art acceptance in 02; 03 uses separate small finished-quality environment.
02B measures local HTTP cold/warm, actual payload bytes, frame times, resources and repeated lifecycle, with explicit limitations on heap/GPU/physical iPhone. Owner playable preview via isolated static artifact or lab link, never replace campaign.
