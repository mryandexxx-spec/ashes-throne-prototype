# NET-001 — технический контракт базового ядра разведсети

**Статус:** [В РАЗРАБОТКЕ] в PR #386, не подключено к опубликованной игре. Числа тестовых примеров — [ПРЕДЛОЖЕНИЕ], не игровой баланс.

## Границы

- `network-data.js`: строгая схема `catalog.version=1`; регионы, шаблоны, типы, уровни, подготовка, подходы, идентификаторы NPC/наград/материалов/героев. `NetworkData.CATALOG` содержит идентификатор первого региона из архитектурного предложения и **ноль игровых шаблонов**. Контент и проверка соответствия мировому канону — NET-003.
- `network-core.js`: чистые функции, без DOM, Babylon, `localStorage`, `Date.now()`, кошелька и боевого ядра. Использует существующий `BattleRng` для предсказуемой последовательности.
- `network.v1` — отдельный ключ `ashes-throne.network.v1`. Существующие `ashes-throne.progress.v3`, `lore-campaign.v1`, `signal-operation.v1` и другие ключи не читаются и не изменяются ядром.

## Создание и вызовы

`NetworkCore.fresh(seed, now, config, catalog)` создаёт состояние. `seed` — явный `uint32`, его необходимо получить **однократно** из криптографически безопасного генератора в будущем интеграционном слое. `now` — переданное целое число миллисекунд UTC, не запрос внутри ядра.

Конфигурация **обязательна** и включает `id`, `capacity`, `intervalMs`, `guaranteeAfter`, `focusWeight`, `masteryScore`. Ни одно число не прошито как утверждённый баланс; меняющаяся совместимость конфигурации требует нового `id` и отдельной миграции.

`accrue(state, now, catalog, unlockedRegions)` добавляет по одной детерминированной зацепке за полный интервал, только при свободных местах. При полной доске часы переставляются на текущее время и переполненная очередь не копится. При переводе часов назад не начисляет зацепок. Если нет ни одного подходящего шаблона, состояние не получает фиктивные задания.

`setOrder(state, {kind,targetId}, catalog, unlockedRegions)` принимает только достижимые цели по известным шаблонам. После `guaranteeAfter` **фактических поступлений** хотя бы одна зацепка удовлетворяет приказу; полная доска не тратит гарантию. Отсутствие подходящей цели приводит к отказу, а не скрытой подмене результата.

`start → prepare → approach → battleOutcome (по волнам) → finish` — модель завершения. Запуск снимает **именно экземпляр** зацепки с доски; повторный старт запрещён. `abandon` и поражение возвращают всю её исходную запись. Если за время боя доска заполнилась, допустимо временное превышение ёмкости на одну зацепку. Победа создаёт самостоятельный монотонно нумерованный `completed` с `status=done`, записывает лучшую ручную оценку для пары `templateId|level` и увеличивает счётчик завершений региона. Дальнейшая симуляция — NET-005, баланс влияния — NET-006.

## Безопасность сохранений

`load(storageProvider, {seed,now,config,catalog})`: без ключа возвращает `fresh` **без записи**. Повреждение JSON, неизвестная версия, неожиданные поля, несовместимая конфигурация и отказ чтения возвращают `blocked`, не затирая данные.

`save(state, storageProvider, ownsLock)`: **fail-closed**. Третий аргумент — обязательная проверка владения сессией `ProgressWriterCore.isOwner` (фактическое подключение — NET-004). Нет владельца — нет записи; сверяется ревизия и подтверждается точное чтение назад. Функция возвращает новый экземпляр состояния с увеличенной ревизией. После неясного результата записи нужно блокировать действия и перезагрузиться: не повторять запись наугад. В будущей интеграции **перед запуском боя необходимо сохранить снятие зацепки с доски и подтвердить readback**. При перезагрузке сохранённая фаза боя — чекпоинт, но сам бой восстанавливает только адаптер NET-003; NET-001 не симулирует боевой движок.

Схема `network.v1` не мигрирует/не изменяет `progress.v3` и не производит выплат. Запись результатов в отдельном ключе не атомарна с начислением кошелька. Контракт `serial` для выплат, подтверждение из состояния сети, защита двойного claim и безопасная очистка оплаченных `completed` — **NET-002**, не NET-001.

## Открытые риски

1. Время устройства, переведённое вперёд, не обнаружить без сервера. Это ограничение локальной игры.
2. Данные и весовой выбор шаблонов, параметры ёмкости, порога освоения, периодов и гарантии требуют оценки и решения владельца в NET-006.
3. `completed` пока сохраняются без выплат и без очистки. Есть технический предел 10 000 результатов; NET-002 должен определить compact ledger/прунинг до интеграции с UI.
4. Смена каталогов не переписывает уже выданную зацепку, но старые идентификаторы `encounterRef` и `rewardRef` должны разрешаться совместимым адаптером. Удалять существующие ссылки без миграции нельзя.
5. Проверка Node/Actions не является тестом на физическом iPhone. UI/3D здесь не менялись.

## Проверки

`npm test` (включая `tests/network-001-core.test.js`) проверяет каталог, детерминизм, приказы, часы, ёмкость, поражение/отказ, повторный старт, сохранённые чекпоинты, освоение, повторную загрузку, повреждённые данные, отсутствие lock и неясную запись. Итоговые числа запусков и CI указывать по фактическому head PR, не по предыдущей ветке.
