# NET-004 — изолированный интерфейс разведсети, пилотная интеграция

**Статус: [В РАЗРАБОТКЕ] / [ПРЕДЛОЖЕНИЕ].** Ветка `feat/net-004-network-pilot-ui` основана на NET-003 PR #388, который зависит от NET-002 #387 и NET-001 #386. Ни одна из четырёх веток не слита в `main`.

## Принципиальная граница

NET-003 содержит только **неутверждённые** тестовые зацепки и числовые параметры. Настоящий `NetworkData.CATALOG` по-прежнему пуст. Поэтому NET-004 не создаёт оплачиваемый игровой режим и не открывает его обычным игрокам.

- Вход доступен **только с явным флагом** `?networkPilot=1` в URL в тестовой сборке, через кнопку меню штаба «Разведсеть · пробный режим». Без флага кнопка скрыта, сеть не инициализируется и не обращается к пилотному хранилищу.
- Все тестовые зацепки сохраняются в **`ashes-throne.network.pilot.v1`**. `NetworkPilotSession` передаёт `NetworkCore` изолированный storage-provider, который отображает ожидаемый `NetworkCore.KEY` *исключительно* в пилотный ключ; напрямую `ashes-throne.network.v1` и `progress.v3` он не читает и не меняет. При повреждении данных — остановка, а не автоматический сброс.
- Исключительная блокировка записи — существующая `ProgressWriterCore.exclusive` и обязательная проверка `isOwner`. Получение новой зацепки, выбор варианта, контрольная точка, сохранение исхода, завершение — отдельные подтверждённые записи с проверкой ревизии/readback. После ошибки записи/потери блокировки действия заблокированы до перезагрузки.
- **Реальных наград нет.** Кнопка «Забрать награду» отключена; фиксация завершения пишет только пилотный результат. В пилоте используется `score=0` как явно показанная техническая заглушка, **не** решение о качестве прохождения или уровне освоения. Настоящие расчёт сложности, оценки и источники наград — отдельная приёмка NET-006.
- Не использовать этот пилотный ключ в будущем продакшене и не считать его базой для миграции игрового прогресса.

## Доступный сценарий

1. Открыть пробный режим через меню штаба с URL-флагом. Новые тестовые профили получают до трёх пробных донесений для быстрого прогона интерфейса, без ожидания реальных таймеров.
2. Доска из трёх пробных шаблонов, счётчик вместимости/условного влияния, кнопка обновления.
3. Выбор конкретной зацепки → подготовка (`survey/cover`) → подход (`quiet/cordon`) → **подтверждённое сохранение фазы `battle`**.
4. Существующий экран отряда (1–5 героев) → действующая Babylon-арена с `NpcEnemyData`, `CombatCore` и текущими визуалами NPC. Фактическая конфигурация создаётся через `NetworkEncounterAdapter.startBattle`; скрипт `game.js` не рассчитывает состав или исход боя.
5. **[УТВЕРЖДЕНО владельцем 18.11.2026] Два отдельных столкновения с полным восстановлением отряда между ними.** Победа в первой схватке → `NetworkPilotSession.complete` с проверенной привязкой к ревизии/волне → подтверждённая контрольная точка следующей схватки; это **не** завершение зацепки и не источник награды. Игрок возвращается на экран сети, затем выбирает отряд и запускает новое столкновение. Новое `CombatCore.createBattle` получает характеристики героев заново из ростера: HP и защита восстанавливаются до исходных значений, эффекты и перезарядки обнуляются; данные предыдущего боя не переносятся. Поражение в любой из двух схваток возвращает ту же исходную зацепку. Только победа во второй переводит зацепку в итоговую фазу.
6. Успешная последняя волна → экран результата → явное «Зафиксировать завершение» → тестовый журнал; никаких выплат. Reload восстанавливает `brief`, `approach`, `battle`, `result` или завершение из пилотного ключа. При перезапуске текущей волны `seed` детерминированный и не даёт повторный случайный исход без новой записи.

## Файлы

- `network-pilot-session.js` — слой транзакций и отдельное хранилище.
- `network-pilot-ui.js`, `network-pilot.css` — оформление в стиле HQ/ROSTER: бронза/графит, касания 44 px, safe-area, `focus-visible`, `prefers-reduced-motion`, без дополнительного 3D вне арены.
- `index.html` — новый скрытый по умолчанию вход/экран, загрузка модулей после wallet gate, версия сборки `0.3.188 · NET004PILOT`.
- `game.js` — только feature flag и шлюзы выбора отряда, создания боя и фиксации исхода, без самостоятельной реализации правил сети.
- `network-encounter-adapter.js` — передача уже существующего лидера отряда в `CombatCore`.
- `package.json`, `tests/network-004-pilot.test.js`, `tests/network-004-pilot-browser.cjs`, `.github/workflows/network-004-tests.yml` — синтаксис/регрессии/два браузера.
- Совместимость старых контрактных Node-тестов со следующими версиями сборки сохранена без изменения самих наград.

## Проверка / ограничения

Целевые сценарии: 772+ старых Node-тестов; два отдельных столкновения с восстановлением HP/защиты/эффектов/перезарядок и reload между ними; пилотное сохранение; двойной запуск; повреждённый профиль; потеря Web Lock; нарушение ревизии; отступление и поражение; сохранённый результат; сценарий `board → brief → squad → real battle → result → reload → finish` в Chromium и WebKit на **844×390** и **932×430**; отсутствие горизонтального переполнения. Сведения о фактическом прохождении CI записывать в PR по последнему коммиту, не по предыдущим итерациям.

**Открытые вопросы:** реальная числовая награда и её подтверждение в `NetworkRewardCore`, формула оценки, ввод утверждённого контента в `NetworkData.CATALOG`, дальнейшая интеграция с Finder/приказом/симуляцией. Физический iPhone Safari не тестировался. Не сливать или публиковать без явного разрешения владельца.
