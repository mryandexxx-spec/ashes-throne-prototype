# NET-006A — оценки S1, контрольные точки и освоение

> **Статус [В РАЗРАБОТКЕ]** — код и тесты в отдельной ветке `feat/net-006a-score-mastery-checkpoints`, draft PR #393 от 18.11.2026. Этот документ **не** объявляет NET-006A выпущенным в `main` и не утверждает экономику E1. Проектное решение S1/P1 зафиксировано в NET-006 и PR #392.

## Назначение и ограничения

В пробной разведсети `?networkPilot=1` вычислять честный результат после каждого отдельного боя. Полностью сохранённая двухволновая зацепка должна давать только **один** итог и максимум одну серийную запись. Оценка S1 не зависит от секунд, автоскорости, анимации и графики. Старые боевые режимы, HP/защита/эффекты между боями, регулярное сохранение прогресса и текущая валюта не меняются.

**Нет настоящих наград:** production `NetworkData.CATALOG.templates=[]`; пилот использует только `ashes-throne.network.pilot.v1` и тестовые `net-proposal-no-payout-*` источники. `progress.v3`, реальные выплаты, баланс M1–M3, осколки и дополнительные ресурсы NET-006A не изменяет.

## S1

Одна подтверждённая победа: `round(60 + 25*(1 - уникальные нокауты/число своих героев) + цель(0|10) + темп(0…5))`. Нокаут учитывается **по событию смерти**, а не по HP в конце боя: последующее лечение/воскрешение его не стирает. Проверяемая цель в текущих тестовых встречах — уничтожить заранее объявленного первого NPC **первым**. Темп зависит только от числа действий союзников; тестовый норматив — `max(5, 5 * число NPC)`, 5 баллов при норме и на один балл меньше за каждое лишнее действие. **Эти цель и норматив для NET-003 fixtures — техническая временная конфигурация, не утверждённый баланс production-контента.**

Для двух независимых столкновений: сохранить `waveSummaries[0]` и `waveSummaries[1]` после каждой победы; итог `round((S1+S2)/2)`. 1★ = 60–74, 2★ = 75–89, 3★ = 90–100. Поражение и добровольный выход возвращают исходную зацепку; не создают завершения, мастерства и наград. Никакого общего буфера HP, защиты, кулдаунов или эффектов между волнами.

## Освоение и обратная совместимость

Освоение при `S_final >= 90` записывается под ключом `templateId|templateRevision|level|modifierId|encounterRef|rewardRef|approach|s1`. Отсутствие модификатора обозначено `-`, это **не** допустимый действительный ID модификатора и не путается со строкой `none`. В `completed` вместе с серией добавляется необязательный `masteryKey`; старые записи по-прежнему валидны. При обновлении сложности, модификатора, подхода, версии шаблона, версии правил, встречи или варианта награды — нужна новая победа.

Старый `template|level` может оставаться в сохранении как исторический результат, **но не даёт** право новой симуляции. `NetworkCore.simulate` принимает только реально сохранённый экземпляр подходящей зацепки и наличие освоения S1. Серийное подтверждение симуляции проверяет именно версионированный `masteryKey`.

**Старые пилотные сейвы** не мигрируются: завершённый legacy-результат остаётся доступен для безопасной фиксации, но не получает S1 задним числом. Если сохранена первая победа старой двухволновой цепочки **без** S1-сводки, интерфейс объясняет несовместимость и не разрешает продолжать второй бой; «Отменить» возвращает исходную зацепку, которую можно пройти заново. Нельзя смешать scored и старую волну и выдать поддельный средний счёт.

Для совместимости изолированных unit fixture-тестов пока оставлен низкоуровневый явный `Adapter.complete(..., legacyScore)` и `NetworkCore.battleOutcome(..., legacyScore)`. Браузерный пилот использует **только** `Adapter.complete(state,battle)`, который сам проверяет привязку к реальному завершённому бою. Legacy-путь не создаёт S1-мастерство и не может стать боевым API с реальными выплатами без отдельного удаления/ограничения.

## Изменения

- `network-score-core.js` — чистое вычисление и валидация S1, компактная история нокаутов/порядка смертей NPC.
- `combat-core.js` — наблюдение death-событий только при наличии сетевого трекера; без новых эффектов и новых боевых правил.
- `network-encounter-adapter.js` — подключение трекера и расчёт результата исключительно из завершённого связанного боя.
- `network-core.js` — durable `waveSummaries`, точный итог, версионированное mastery, запрет смешивания протоколов, совместимые старые структуры состояния.
- `network-reward-core.js` — запрет серийного доказательства симуляции без S1-мастерства; выплат не добавлено.
- `network-pilot-session.js`, `network-pilot-ui.js`, `game.js` — score вместо заглушки 0, заранее показанная цель, детали волн, корректное сообщение о старом checkpoint.
- `index.html`, `package.json` — веточный билд `v0.3.190 · NET006ASCORE`, версионированная загрузка нового скрипта.
- `tests/network-006a-score.test.js` + обновлённые тесты NET-002/003/004/005 и их браузерные ожидания.
