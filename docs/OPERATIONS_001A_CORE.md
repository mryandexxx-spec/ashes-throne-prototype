# OPS-001A — изолированное ядро разведывательной операции

**Статус:** [В РАЗРАБОТКЕ] — технический этап в отдельном PR; до слияния не в `main`.
**Дата:** 2026-11-08.
**Контекст:** владелец выбрал смешанный режим «разведка + тактика + бой», затем ответом «Ок» принял базовый цикл «два приказа → выбор перехвата → бой → заключительное решение». Это **не утверждение канонического сюжета, имен, баланса и наград**.

## Границы OPS-001A

Добавлены только `operation-core.js` и его Node-тесты. **Никакие кнопки в игре пока не появляются**, `game.js`, `index.html`, боевой движок и схема профиля не изменяются. Новая версия опубликованной игры этому этапу не присваивается.

Тестовое название «Два курьера», два опознавательных знака и конфигурации A/B — [ПРЕДЛОЖЕНИЕ], исключительно для проверки логики.

## Правила чистой модели

- Новый запуск: `start(variantId, runId)`. `runId` — непустой уникальный идентификатор, который позже должен выдаваться интегрирующим кодом; само ядро случайность не генерирует.
- Такт 1: `register` / `block` / `extract`. Такт 2: `observe` / `register` / `extract` в зависимости от первого выбора, без повторений. При `block` наблюдение недоступно.
- `intel(run)` раскрывает только заработанные факты: знак подлинника при `register`, соответствие знаков двум маршрутам при `observe`.
- `targetAssessment(run, target)`: `confirmed` / `disproved` / `unconfirmed`; `guaranteed` для перекрытой развилки. Не запрещается осознанно выбрать неподтверждённый или опровергнутый маршрут.
- `intercept` фиксирует выбранное направление до боя. `battlePlan` возвращает только `singleWave` или `twoWaves` и указание на контрольную точку перед боем. **Данные врагов и боевой движок не подключены**.
- `battleEnded` принимает финальное `active:false` с `winner:ally|enemy` и проверяет `runId`. Победа на неправильном маршруте — `wrongTarget`, поражение — `defeat`.
- После успешного перехвата `finish` поддерживает `cover`, `ledger`, `leave` и `both` только при подготовленном отходе.
- `abandon` доступен до боя, а также на контрольной точке перед повтором незавершённого боя (уточнение OPS-001B); отказ никогда не считается победой.
- Функции переходов возвращают новый объект и не меняют входное состояние; недопустимое действие даёт `null`.

## Отдельное сохранение

Ключ — `ashes-throne.operations.v1`, версия схемы 1. `fresh / stage / load / save` управляют активным запуском и последними 20 локальными итогами, без звёзд/экономики.

- Изолировано от `ashes-throne.progress.v3`, `ashes-throne.campaign.v1` и `ashes-throne.challenges.v1`.
- Схема проверяет допустимые фазы, приказы и исходы; неизвестные поля и повреждённые записи блокируют запись, а не затираются.
- При прерывании Safari на фазе `battle` сохраняется **только план до боя**; OPS-001B сможет запустить бой заново с начала.
- Итог сначала рассчитывается и формирует новый кандидат; интеграция обязана успешно записать его перед объявлением постоянного результата.
- Архивирование завершённого `runId` исключает повторный учёт того же исхода через штатные API. В будущем UI обязан также отфильтровывать устаревшие колбэки.

## Проверки

`tests/operations-001-core.test.js` проверяет:
- честное раскрытие двух независимых улик в обеих конфигурациях;
- все шесть подготовительных путей в обеих конфигурациях;
- блокаду, две волны, верный и ошибочный перехват, поражение, добровольное прерывание;
- запрет повторных приказов/колбэков, старый идентификатор боя и недопустимый финальный выбор;
- отдельную историю, контрольную точку, сбой хранилища и неперезапись повреждённых данных.

`npm test` использует `node --test tests/*.test.js` и автоматически включает новый тестовый файл.

## Ограничения и следующее согласование

Это **не завершённый игровой режим**. Пока отсутствуют мобильная карта, интеграция выбора доступных героев, запуск одной/двух волн в существующем бою, кнопки и экран итогов. Проходимость двух волн на стартовом составе не измерена. Ни баланс, ни экономика, ни канон не меняются.

Следующий отдельный этап **OPS-001B** — интеграция в UI/бой с регрессионными тестами. Начать его после рассмотрения и принятия текущего PR; слияние только по разрешению владельца на **этот конкретный PR**.
