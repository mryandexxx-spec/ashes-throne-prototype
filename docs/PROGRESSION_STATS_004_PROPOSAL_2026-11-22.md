# PROGRESSIONSTATS004 — согласованная по смыслу, предварительная по числам модель развития

**Статус:** [ПРЕДЛОЖЕНИЕ — числовой баланс не утверждён]. Дата: 22.11.2026.  
**Источники:** GDD 3.0 §11.2–11.4 (числовые формулы усиления TBD), действующие StarCore / ProgressCore / HeroStatsCore / HeroStatsCombatBridge / HeroStatsProfiles в `main`; принятое владельцем требование увеличить разнообразие изменений по уровням, звёздам и G-рангу. Следующее экономическое моделирование модели B по дорожной карте отложено, поэтому числа **не окончательный баланс**.

## Вывод аудита

- У **уровня** уже есть прирост HP, Protection, физ. атаки, физ./маг. обороны через `growth.level`, но оборона и малые значения округляются: на отдельном уровне часто меняются только 2–3 видимых показателя.
- **Звёзды** в реальном бою `HeroStatsCombatBridge` усиливали по +3% от базового значения только HP, физ./маг. атаку и физ./маг. оборону. Поля `growth.star` содержали устаревшие первичные прибавки, не используемые боем; их удалили, чтобы не было второго источника.
- **Шесть предметов** уже дают накопительные индивидуальные flat `statBonuses` через историю. **Сам переход G** добавлял только +3 процентных пункта постоянного бонуса HP и физ. атаки.
- `HeroStatsCore.KEYS` хранит 14 боевых характеристик. Их все сравнивает окно награды (VICTORYSTATS003); недостаток был именно в генерации характеристик.

## Предлагаемая модель

**[СОХРАНЕНО БЕЗ ИЗМЕНЕНИЙ]:** 1–85 уровень, 1–7 звёзд, 1–13 G, +3% от профиля за звезду в пяти первичных параметрах; каждый G добавляет по 3 процентных пункта HP/физ. атаки; каждый слот даёт бонусы ровно один раз, включая историю. **Обычная прокачка не увеличивает Speed.** Не добавляются магические атаки персонажам с базовой `magicAttack=0`. Формулы боевого урона и порядок ходов не меняются.

### 1. Уровень — индивидуальная специализация героя

Сохраняются прежние прибавки HP, защиты, атаки и обороны из `growth.level`. Дополнительно в том же профиле задаются *прибавки в процентных пунктах за один уровень* (дробные значения хранятся, не округляются каждый уровень):

| Герой | Промежуточная вторичная специализация на каждый уровень |
|---|---|
| Рен | +0,06 критшанс, +0,11 точность, +0,07 пробивание, +0,06 сопротивление ослаблениям |
| Нада | +0,14 эффективность ослаблений, +0,10 сопротивление, +0,08 точность, +0,04 уклонение |
| Лиора | +0,10 уклонение, +0,12 сопротивление, +0,04 точность |
| Арт | +0,08 критшанс, +0,09 пробивание, +0,05 сопротивление |
| Сава | +0,13 точность, +0,07 уклонение, +0,11 эффективность ослаблений, +0,04 сопротивление |

**Почему:** уровень даёт плавный и понятный рост, не заставляя все 14 чисел расти одинаково.

### 2. Звезда — базовые параметры и индивидуальная устойчивость

Оставляем +3% за звезду к пяти базовым параметрам из `StarCore.COMBAT_BONUS_STATS`. Дополнительные **flat за звезду** определяются только вторичными ключами `HeroStatsProfiles.growth.star`; ни HP, ни физическая атака не считаются дважды.

| Герой | Вторичные прибавки за одну звезду |
|---|---|
| Рен | +5 Protection, +0,35 критшанс, +0,25 точность, +0,20 пробивание |
| Нада | +7 Protection, +0,65 эффективность ослаблений, +0,35 сопротивление, +0,25 точность |
| Лиора | +8 Protection, +0,30 уклонение, +0,50 сопротивление |
| Арт | +6 Protection, +0,40 критшанс, +0,30 пробивание |
| Сава | +5 Protection, +0,45 точность, +0,25 уклонение, +0,30 эффективность ослаблений |

**Почему:** звёзды должны усиливать характерные достоинства героя, а не увеличивать всю таблицу на один и тот же процент. StarCore и число осколков не меняются.

### 3. G-ранг — универсальная выживаемость и специализация класса

При **каждом переходе G → G+1** (только для реального `mode=itemized`) сохранён существующий +3 п.п. бонус к HP/физ. атаке. Дополнительно начисляется: **+2 Protection, +1 физическая оборона, +1 магическая оборона**. Один параметр определяется существующим `progress.classes[id]`:

| Класс | Добавка за G-ранг |
|---|---|
| melee | +0,25 п.п. к критшансу |
| ranged | +0,25 п.п. к точности |
| mage | +0,35 п.п. к эффективности ослаблений |
| support | +0,35 п.п. к сопротивлению ослаблениям |
| tank | +1 Protection |

Бонусы рассчитываются по `state.tier - 1`; не записываются отдельными значениями в сохранение и потому не требуют миграции. Индивидуальные свойства всех установленных вещей по-прежнему суммируются по истории. Демонстрационный (не-itemized) путь оставлен без нового бонуса.

## Устройство и границы

- **Данные:** `HeroStatsProfiles.growth.level/star`, `ProgressCore.GEAR_PROMOTION_FLAT_BONUS/GEAR_PROMOTION_CLASS_BONUS`.
- **Расчёт:** `HeroStatsCombatBridge` применяет 3%-ную звёздную формулу один раз и отдельные профильные вторичные прибавки. `HeroStatsCore.resolve` остаётся единым валидатором/округлителем всех 14 параметров.
- **UI:** никакого нового списка параметров в окнах — VICTORYSTATS003 показывает реальные изменения.
- **Сейв:** только исходные `level/stars/gear`; цены/материалы/осколки неизменны, итог покупки как раньше показывается только при сохранении.
- **iPhone:** никаких новых изображений, текстур, WebGL и интервалов; не создаётся дополнительной нагрузки.

## Риски и следующая проверка

1. В результате суммарного роста игрок станет сильнее, но противники и цены не перенастраиваются. Это отдельная задача баланса модели B; нельзя объявлять её выполненной.
2. Перед принятием цифр нужен сравнительный контроль уровня 1/20/40/85, звёзд 1/7, G1/G13 и классов, обрезки процентов [0,100], физического и магического урона в реальных боях. Сильнейшие составы и скорость прохождения существующих испытаний требуют дальнейшего анализа.
3. Приросты дробных процентных показателей реальны, даже когда на визуальной панели другие числа округлены. Проверять `HeroStatsCore`, не выводить фиктивные гарантии «+5 характеристик» для любых пользовательских состояний.
4. **Решение владельца:** после испытания этой временной модели оставить коэффициенты, пересмотреть их или вернуться к прежним. Не превращать этот документ в утверждённый баланс одной записью в `main`.
