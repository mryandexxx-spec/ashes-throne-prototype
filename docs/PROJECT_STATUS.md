## 2. Что есть в игре сейчас

Всё ниже — рабочий прототип вертикального среза. Числа, тексты и большинство героев демонстрационные, это не утверждённый контент и не баланс.

- **Штаб** — художественное главное меню с активными зонами (HQ-UI-004…008).
- **Коллекция и карточка героя** — утверждённая раскладка HEROCARD001: герой в полный рост в центре, умения слева, шесть слотов экипировки, уровень и звёзды справа, подробности в диалогах. Есть экипировка G1–G3, повышение умений, звёзды (до 7★) и осколки.
- **Герои с 3D-моделями:** Рен (2,86 МБ) и Нада (3,1 МБ). Остальные бойцы — демонстрационные фигуры.
- **Режимы:** кампания (глава I, 3 демонстрационные миссии, звёзды за выполнение условий, волны); испытания и симуляция; разведывательные операции и сигнальный пост; задания дня; семидневный календарь входа; профиль игрока с уровнем аккаунта, который ограничивает уровень героев; сюжетная проба «Сады над бездной».
- **Бой:** ручной пошаговый бой по шкале инициативы 0–1000, выбор цели касанием 3D-фигуры, активные, пассивные и лидерские умения, эффекты, добровольный автобой со скоростями 1×/2×/4×, ИИ противников, журнал боя. Арена построена по образцу Dune (ARENA-ENGINE-003): World HUD над головами без наложений, формация 3+2, FOV 34°.
- **Загрузка 3D:** панель прогресса под шапкой справа, скрывается через 4 с после «в кеше». Service Worker `model-cache-sw.js` кеширует только два GLB (Рен, Нада), имя кеша привязано к хешу модели. На экономии данных, 2G/3G и в скрытой вкладке фоновая загрузка отключена.
- **Сохранение:** только локальное (`localStorage`, версионированная схема v3 с миграциями). Сервера, аккаунтов и монетизации нет.

## 3. Техническая основа (кратко)

- Статический сайт без сборщика и npm-зависимостей во время работы. Скрипты подключаются по порядку в `index.html`.
- Babylon.js **9.33.2** с CDN.
- Логика (бой, прогресс, режимы) разнесена по модулям `*-core.js`, `*-data.js` без DOM. `game.js` — интерфейс и связка экранов.
- 3D-ассеты: `dev/assets-src/` (исходники и паспорта), `dev/assets/models/` (игровые GLB), `dev/src/assets/models.js` (реестр). Рен пока загружается из `assets/ren-meshy-mixamo-animated.glb`, вне этой структуры.
- Проверки: `npm test` = `node --check` для 46 из 53 корневых JS-файлов (плюс `dev/src/assets/models.js`) и `node --test tests/*.test.js`. Браузерные проверки (Chromium/WebKit, Playwright) — в 13 workflow GitHub Actions.
- **TDD 1.0 описывает исходный стартер из 4 файлов и фактическую архитектуру не отражает** (см. раздел 5).

## 5. Открытые проблемы и технический долг

1. **Процесс: ARENA-ENGINE-003 попал в `main` прямым коммитом `7be7ffe`**, а не через PR #283, хотя слияние не разрешалось. Содержимое уже в игре, PR #283 остаётся открытым. Нужно решение владельца: принять задним числом или пересмотреть.
2. **TDD 1.0 устарел:** описывает стартер, а не текущую модульную архитектуру с Service Worker и реестром ассетов. Нужна редакция TDD 1.1.
3. **Открытые PR:** по аудиту владельца около 36, большинство устарели (серия ENV #180–#240, старые подходы к Рену #244/#246, поглощённые #278/#281/#282/#283 и др.). Нужна разборка, закрывать только с согласия владельца.
4. **Модель Нады** `dev/assets/models/nada-mobile-animated.glb` — 3,1 МБ (JPEG 2048, анимации без сжатия). Кандидат на оптимизацию по образцу RENOPT001.
5. **Тесты кода сборки:** 19 тестовых файлов жёстко проверяют код текущей сборки, поэтому каждый подъём версии затрагивает много файлов. Кандидат на единый источник версии.
6. **`npm test`:** `node --check` не охватывает 7 корневых файлов: `arena-stage-view.js`, `daily-core.js`, `login-core.js`, `model-cache-client.js`, `model-cache-sw.js`, `ren-3d-studio.js`, `ren-glb-review.js`. При этом `arena-stage-view.js` покрыт `tests/arena-stage-view.test.js`. Остальные файлы, вероятно, тоже подключаются тестами, но это не сверялось.
7. **Мобильная приёмка:** после HEROCARD001, ARENA-ENGINE-003, CACHE001/002, RENOPT001 и MOBILEQA001 полный чек-лист на физическом iPhone Safari не проходился.
8. Отдельного Roadmap нет. Направление развития задаёт GDD 3.0, этапы — раздел 6.
