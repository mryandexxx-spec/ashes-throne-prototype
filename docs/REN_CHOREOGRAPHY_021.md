# RENCHOR021 — базовая атака Рена [В РАЗРАБОТКЕ]

Кандидат v0.3.121, PR #262. Не сливать без разрешения владельца. Художественная приёмка не завершена.

## Диагностика

PR #262 смешивал несовместимые шкалы: Running 0–30%, удар 30–74%, обратный Running 74–100%, тогда как BattleAnimation.approach двигал anchor вперёд до 38%, держал до 64% и возвращал с 64%. Дополнительно pose.x/y/tilt накладывались на скелет. Даже после фиксации Hips модель продолжала двигаться во время удара. Полное обнуление X/Z всех клипов уничтожало боковой перенос веса и небольшую циклическую работу таза.

Настоящий GLB прочитан бинарно и проигран в Babylon 9.33.2 NullEngine (это НЕ WebGL): Running 0.633333 с; Walking 1.033333 с; Double_Combo_Attack 2.833333 с. Babylon использует 60 fps в AnimationGroup, исходные glTF ключи — 30 fps. Нельзя считать кадр Babylon равным номеру ключа. Hips Z комбо начинается -1.045388 и заканчивается -0.002804 м; первый удар не использует весь метр перемещения.

## Архитектура кандидата

- Отдельный чистый RenChoreography: расстояние, измеренная root-кривая, разгон/торможение, сегменты, контакт. Одна шкала времени для позиции, скелета и FX. ×1/×2/×4 меняют только скорость этой шкалы.
- Для basic выделен первый взмах комбо, Babylon frames 0–60 (1 с), затем переход к стойке. Кандидат контакта frame 39, по быстрому первому нисходящему взмаху кисти. Это технический ориентир, не доказательство соприкосновения оружия.
- Ключи GLB не меняются. При сэмплировании basic горизонтальный Hips заменён idle-опорой; точная исходная X/Z-дельта перенесена на anchor с учётом масштаба и направления. Вертикальное движение и кватернионы сохранены. Бег/ходьба/idle/смерть используют исходные ключи.
- Фаза Running/Walking привязана к фактически пройденному расстоянию, включая разгон и торможение; план сохраняет масштаб и калибровку, загрузка GLB не меняет уже запущенный план. При недоступном GLB действует прежняя fallback-подача.
- Переходы детерминированы: два сэмпла AnimationGroup через start/pause/goToFrame, TRS lerp и quaternion slerp. Буферы поз создаются при загрузке, Babylon-ресурсы в кадре не создаются.
- Только basic получает новый план. Special/powerful не объявлены исправленными.
- Реакция и FX basic Рена запускаются на контакте, расчёт урона остаётся прежним. Смерть/результат ждут завершения очереди. Выход/повтор очищают незавершённые сигналы.

## Стенд

`ren-combat-lab.html`, без ссылки из основного меню. Работают запуск/пауза/повтор/сброс, расстояние 2.5–8 м, скорости, точный ползунок, переходы к фазам, три ракурса, исходные полные клипы. Показаны anchor, gap, время контакта, кисть и поверхность цели.

Preview: https://raw.githack.com/mryandexxx-spec/ashes-throne-prototype/fix/ren-root-motion-choreography-020/ren-combat-lab.html — подтвердить версию; посредник может показать Open the page. Требуется WebGL.

Альтернатива: checkout ветки, `python3 -m http.server 8765`, открыть `/ren-combat-lab.html`. CI `tests/ren-choreography-webgl.cjs` сохраняет снимки фаз, два дополнительных ракурса контакта, video и measurements.json в artifact `ren-choreography-webgl`.

## Проверки и ограничения

Локально npm test: 323/323. Включены реальные данные root-кривой из GLB, непрерывность фаз на трёх дистанциях, направления, контакт ×1/×2/×4, смерть/clear, повтор, регрессии остальных акторов, игровой UI со смертью/результатом/повтором. Это технические проверки, не художественная приёмка.

Локальный Chromium не стартует: socket() Operation not permitted; облачный браузер сообщает WebGL not supported. Первый CI запустил реальный WebGL, прошёл численные проверки траектории и сохранил видео, но упал по тайм-ауту захвата скриншота. Исправлен захват: render loop останавливается для детерминированных кадров; массовые проверки поз не отправляют тысячи кадров в GPU. Новый полный CI ожидается. Старый зелёный CI на 5ee61894 не относится к RENCHOR021.

Кандидат дистанции рассчитывается при загрузке по мировой позиции правой кисти на frame 39 и радиусу существующей цели .42 м. Момент контакта, обрезка первого взмаха и backward Walking должны быть проверены визуально. Отдельного backward-клипа нет. Отсутствие скольжения стоп и реальное попадание оружия пока НЕ подтверждены. iPhone Safari не проверен.

GDD 3.0 (`Pepelny_tron_GDD_3.0.md`) и TDD 1.0 (`Pepelny_tron_TDD_1.0.md`) найдены в проектных файлах и прочитаны. TDD — предложение, не описание нынешней реализации; GDD закрепляет мобильный landscape, ручной бой, ускорение и отдельную визуализацию. Игровые правила не меняются.
