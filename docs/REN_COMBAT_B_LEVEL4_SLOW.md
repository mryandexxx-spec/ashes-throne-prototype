# REN-COMBAT-B — «Точный удар»: замедление с уровня 4 (сюжетная проба)

**8 ноября 2026 · [В РАЗРАБОТКЕ, отдельный PR]**. Срез интеграции REN-001 и REN-COMBAT-A; боевые значения пока **[ПРЕДЛОЖЕНИЕ / ТЕСТОВЫЕ]**, не утверждённый баланс.

## Авторские требования и пределы
**[УТВЕРЖДЕНО]** Рен относится к классу `melee`, его тег — «Сады над пропастью»; «Точный удар» накладывает замедление **только с уровня способности 4**, а не с уровней 1–3.

**НЕ УТВЕРЖДЕНО:** величина замедления, срок, числовые усиления урона для уровней, формула сопротивления наложению, параметры пассивки, итоговое название мощного навыка и хронология литературного героя. Из REN-001 для проверки временно выбраны **-20% скорости на 2 собственных хода цели**. Это тестовая гипотеза, может быть заменена до общего релиза.

## Реализация в этом срезе
- `AbilityData`: у сюжетного `trial-ren` собственное имя базовой способности «Точный удар · проба»; при наличии `skillLevels.basic` 4–6 в декларативном `onHitStatus` появляется `{type:"slowed",amount:20,turns:2}`. На уровне 1–3 поля нет. Урон оставлен 100% исходной атаки на всех уровнях, без притворной окончательной прогрессии.
- `StoryTrialData`: для воспроизводимой пробной сцены назначен **временный 4-й уровень** `skillLevels.basic:4`. Это не улучшение персонажа и не сохранение. Рен не появляется в `SkillCore.HERO_IDS` или постоянной коллекции.
- `CombatCore`: обрабатывает `onHitStatus` **по данным способности**, а не по конкретному ID Рена; статус возникает только после успешного попадания по оставшейся живой цели; не даёт пропуска хода. `CombatStatusCore.effectiveSpeed` участвует в уже существующей системе инициативы, исходная `fighter.speed` не меняется. Длительность уменьшается после собственного успешно выполненного действия замедленной цели. Повтор не складывает силу/длительность.
- `AbilityInfo`, `game.js`: подпись тестовых параметров, индикатор замедления над бойцом и пояснение в просмотре бойца. `index.html` загружает модуль статусов до `combat-core.js`.
- Сохранён общий метод исполнения для ручных, автоматических и вражеских действий, что снижает риск расхождения режимов.

## Предохранители и известные ограничения
- **Экспериментальная модель `statusChecks:true`** по умолчанию недоступна для новой способности: команда отклоняется **до траты действия**, пока не согласованы формула сопротивления и бюджет RNG. В текущей сюжетной пробе режим без проверок сопротивления; замедление при попадании гарантировано. Это именно **ограниченный прототип**, а не утверждение будущего баланса.
- `debuff-resistance-down` технически есть в отдельном модуле, но пока не назначен способности; его влияние на сопротивление наложению ждёт отдельного этапа.
- `onHitStatus` сейчас поддерживает одну статусную запись на удар. Общая система статусных комбо и пассивка «Чувство тропы» **НЕ реализованы**.
- При гибели цели на ударе замедление не создаётся. При смене волны новые враги создаются без статусов; выжившие союзники сохраняют свои состояния как и раньше.
- Новые эффекты не включены в сериализацию v3, потому что они исключительно временные боевые состояния. Не добавлялись никакие материалы, слоты или платные улучшения.

## Проверки

Общий GitHub CI обязателен. Проверка iPhone Safari и фактической анимации — отдельно после слияния.

**Важное UX-уточнение:** у Рена пока нет постоянной карточки в коллекции. Для ручной проверки: «Кампания» → сюжетная проба «Сады над пропастью» → бой → обычная атака Рена по выжившему противнику → индикатор ⇣ / просмотр бойца. Боевые значения тестовые; авторская приёмка предыдущего SVG — без подтверждённого просмотра на реальном устройстве.
