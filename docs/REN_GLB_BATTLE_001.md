# REN-GLB-BATTLE-001 — экспериментальный анимированный Рен в бою

**Статус:** [В РАЗРАБОТКЕ] технический пилот; художественная приёмка и проверка на реальном iPhone Safari не выполнены.

## Источник

Основа — исходный GLB Рена, скачанный владельцем из онлайн-конвертера. Новый файл `Ren_Teren_animated_v02.glb` создан ранее как экспериментальный 19-костный риг с пятью тестовыми анимациями, без доработок лица. Он был проверен локально, но движения и деформации ещё грубые. **Бинарный файл не попал в этот PR:** доступные операции GitHub не переносят байты вложения из беседы напрямую в репозиторий. Пока владелец сам выбирает GLB через файловый диалог телефона.

## Использование после отдельного разрешения владельца на merge

1. Сохранить на iPhone файл `Ren_Teren_animated_v02.glb` из беседы в «Файлы».
2. Открыть игру по ссылке `https://mryandexxx-spec.github.io/ashes-throne-prototype/?renModel=local`.
3. Войти в бой с Реном в составе отряда.
4. Нажать «GLB Рена», выбрать локальный GLB.
5. Во время боя Рен отображается импортированным 3D-мешем. Его движение связано с имеющимися слотами `idle`, `basic`, `special`, `powerful`, `guard`, `ward`, `hit`. Для смерти временно используется реакция на удар и штатный общий tilt/fade.
6. Кнопка «↶ Рен» возвращает прежний процедурный вид **без перезагрузки**.

В обычном адресе игры без `?renModel=local` нет ни загрузки GLB, ни дополнительного интерфейса и сохраняется прежний Рен.

## Изоляция и ограничения

- `ren-glb-battle.js` загружает Babylon GLB loader **только после выбора файла** и никогда не отправляет файл на сервер.
- Не затрагиваются боевые формулы, выбор целей, здоровье, прогресс, сохранения и роль Рена.
- Точка прикрепления — существующий `meshes.ren.body`, так что позиция, выбор цели и реакции на действия остаются совместимыми со штатной системой.
- Babylon Scene/Engine по-прежнему управляются боем. Визуализация прекращается вне боя; повторные входы в бой не создают новый GLB сами по себе.
- Пилот работает с **точными именами клипов** версии v0.2. Он не доказывает визуальную корректность привязки или качества анимации.
- Проверки Node не равны фактическому WebGL на Safari. Перед использованием в основном бою нужно проверить визуализацию, выбор целей, атаку, урон, смерть, конец боя, повторный запуск, возврат на главный экран, landscape и частоту кадров.
