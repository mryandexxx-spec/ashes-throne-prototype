# REN-MH-004 — модель Рена по производственному методу Дункана

**Статус: [СОБРАНО И БИНАРНО ПРОВЕРЕНО В CI], визуальная/мобильная приёмка [В РАЗРАБОТКЕ], художественный результат [ПРЕДЛОЖЕНИЕ].**

Этот PR создаёт воспроизводимый генератор нового 3D-ассета Рена и отдельную сборку в GitHub Actions. Он НЕ заменяет опубликованный GLB и НЕ утверждает, что новая модель уже прошла художественную и мобильную приёмку.

## Проверенные источники и приоритет

- Мир: WORLD_STATUS.md, regions/gardens-over-abyss/CURRENT.md, characters/REN_AND_NADA_1.0.md в приватном репозитории мира.
- Игровые решения: актуальные docs/PROJECT_STATUS.md, docs/AI_WORKFLOW.md, GDD; фактический игровой main и принятый визуальный подход A+B.
- Производственная технология: mryandexxx-spec/Dgoh-game, dev/models/mhlib.py, mh_body.py, mh_duncan.py, mh_duncan_bake.py, mixamo_clips.py, dev/src/render3d/characters/authored.js.

В Dgoh-game Дункан строится из исходного MakeHuman-меша, дополняется авторской одеждой, развёртками, текстурами, весами для костей и анимациями, экспортируется в Babylon-совместимые данные и GLB. Здесь используются адаптированные средства MakeHuman, но новая одежда/снаряжение проектируются именно для Рена.

## Образ Рена

**[УТВЕРЖДЕНО ДЛЯ ИГРОВОГО ВИЗУАЛА]** Проводник Садов над пропастью, тёмные волосы, многослойная выношенная одежда землистых/оливковых тонов, терракотовый шарф, ременная система, походное снаряжение и страховочная верёвка. Без выдуманного вооружения, геральдики и тяжёлых доспехов.

**[ПРЕДЛОЖЕНИЕ]** Конкретные параметры MakeHuman, лицо, UV/материалы, длина одежды и пластика анимаций — НЕ новый литературный канон; требуются сравнение с одобренным игровым портретом и художественная правка.

## Структура этапа

- tools/ren-mh-build/mhlib.py: перенесённый из Dgoh-game загрузчик MakeHuman с переносимыми путями.
- tools/ren-mh-build/mh_body_ren.py: адаптированные пропорции и морфы, создание MakeHuman тела/глаз/ресниц с весами.
- tools/ren-mh-build/build_ren.py: костюм и снаряжение поверх анатомической основы, экспериментальные текстурированные материалы, 15-костный скелет, 5 именованных анимаций и Blender-export в GLB + .blend.
- tools/ren-mh-build/validate_glb.py: реальная бинарная проверка GLB 2.0, мешей, skin и набора клипов.
- .github/workflows/ren-mh-character.yml: Blender-сборка на выделенном CI runner; результаты загружаются в артефакт ren-mh-004-review-candidate.

## Сборка

В GitHub Actions запустить workflow REN-MH-004 experimental character build для ветки PR, либо дождаться проверки самого PR. Runner получает MakeHuman mesh/rig/weights/targets из проекта MakeHuman Community и Blender через apt. Готовые GLB, blend, текстуры и manifest доступны в артефакте workflow; исходный игровой assets/ren-animated-v02.glb при этом НЕ изменяется.

Прежде чем заменить старый GLB, нужно:
1. [ВЫПОЛНЕНО] Успешно собрать модель и проверить бинарный GLB в GitHub Actions.
2. Осмотреть front/side/back/face, найти клиппинг одежды, аномалии кожи, лицевые ошибки, дефекты весов и движения.
3. Проверить размер ассета, полигоны, PBR, корректность 5 клипов в Babylon.js; затем оптимизировать под iPhone.
4. В следующем отдельном PR при необходимости обновить производственный GLB, импорт в бою и карточке; прогнать WebGL Chromium, регрессию боя, повтор, смерть, lifecycle, iPhone Safari landscape.
5. Запрашивать отдельное разрешение на слияние каждого PR.

## Ограничения и неготовые части

- В текущем генераторе есть альбедо-текстуры и PBR roughness/metallic, но ещё **нет** сопоставимого с Дунканом проверенного высокополигонального baking normal/AO, LOD и детальной работы с лицом.
- В рабочем окружении ассистента Blender отсутствует; фактическая сборка выполнена в GitHub Actions. Это подтверждает экспорт и структуру, но не художественную пригодность.
- Нет визуальной и физической iPhone-приёмки.
- Описания игры, игровой код, gameplay, балансы, сохранения, GDD и канон не меняются. Поскольку версия опубликованной игры не меняется, package.json и футер намеренно оставлены прежними.

Это инженерный прототип конвейера, который нужно проверить и довести, а не объявлять новым игровым ассетом.
