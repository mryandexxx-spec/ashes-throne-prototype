# Stats-001D0 — воспроизводимая случайность для тестового боя

**Дата:** 2026-11-08. **Статус: [В РАЗРАБОТКЕ] — отдельный PR, не слит.**
**Предпосылка:** владелец ответил «Ок» на предложение начать Stats-001D0 без введения новых вероятностных характеристик. Это не утверждение формул шанса попадания, критического удара или сопротивления.
**Основания:** docs/STATS_001A_14_STAT_FOUNDATION.md, docs/Combat_Specification_1.0.md, docs/STATS_001C_DEFENSE_PROTECTION_PROPOSAL.md и исследование Stats-001D/E из открытого PR #116 (исследование не канон).

## Что добавлено

- `battle-rng.js`: отдельный детерминированный генератор LCG с 32-битным беззнаковым состоянием. Создание из seed [0..4294967295], снимок `snapshot`, восстановление `restore`, `roll(battle,chance)` для шанса от 0 до 100 процентных пунктов. Это техническая единица API, **а не утверждённая единица любой из 7 будущих характеристик**.
- `CombatCore.createBattle(heroes,waves,{rngSeed})`: при явно переданном seed добавляет независимый `battle.rng = {seed,state,draws}` к объекту боя. Без seed не добавляет поле, не инициализирует случайность и не меняет существующий ход боя. Если нет загруженного `BattleRng`, seeded-вызов отклоняется до начала боя; обычные вызовы совместимы со всеми старым тестовыми VM.
- `index.html` загружает battle-rng.js **перед** combat-core.js. `package.json` выполняет синтаксическую проверку нового файла.
- Тесты проверяют одинаковые последовательности при одинаковом seed, продолжение после JSON roundtrip снимка, 0%/100%, отсутствие расходования случайности на недопустимых параметрах, независимость потоков и полную неизменность исходов, бойцов и событий старого боя. Никакие случайные броски текущими способностями **не выполняются**.

## Инварианты

1. Без явного seed: нет поля `rng`; весь существующий бой, лидерство, инициативы, миссии, награды, AI, сохранения и шкалы работают как прежде.
2. Один seed + одинаковая последовательность вызовов `roll` дают одни и те же результаты во всех JS-движках с поддержкой `Math.imul`. Используется 32-битная арифметика, никакой `Math.random`, Babylon, времени или FPS.
3. Одно обращение `roll` потребляет **один** случайный шаг даже для 0% и 100%. При неверном шансе, сломанном состоянии или переполнении счётчика генератор не меняется. Выдаётся `{hit,value,draw}`: `value` в полуинтервале [0,1), `draw` — номер броска.
4. `snapshot` и `restore` работают со значениями без ссылок на состояние источника. Это не сохранение незаконченного боя: нынешний `progress.v3` **не содержит** боевого rng, seed или историю бросков.
5. **Никаких боевых событий** промаха, крита, блокировки статуса сейчас не создаётся. `damage`, `hpDamage`, `protectionDamage`, `events` и их формат не менялись.
6. Генератор **не является криптографическим** и не предназначен для безопасного PvP, честного казино или защиты от читов. В будущем нельзя использовать постоянный seed для реальных боёв без отдельного решения о происхождении seed, перезапусках и сохранении.

## Контракт будущего Stats-001D1/D2 [ПРЕДЛОЖЕНИЕ, НЕ РЕАЛИЗОВАНО]

- Нацеливание и проверку *всех* числовых полей перед действием выполнить атомарно.
- Один hit-roll на каждую живую цель (фиксированный порядок), при hit отдельный crit-roll для той же цели; проверить поведение поддерживающих и массовых умений.
- Уточнить, будет ли на промах отдельный `miss` event либо стабильный `damage` с флагом `miss`. Утвердить контракт до реализации UI/лога, не выдумывать событие сейчас.
- При запрещённом действии боевой генератор не должен двигаться, а при автодействии порядок бросков должен быть тем же, что при ручном выборе той же команды.
- Не назначать значения `accuracy`, `evasion`, `critChance`, `critDamage`, `defensePenetration`, `debuffPotency`, `debuffResistance` игровым героям без отдельного решения.

## Проверки / следующий этап

`tests/stats-001d0-battle-rng.test.js` — техническая регрессия воспроизводимости и совместимости боевого состояния. Старые тесты игры проходят на том же `main`-балансе, потому что обычный бой RNG не вызывает. Для отдельного Stats-001D1 потребуется утвердить формулу попадания, правила промаха, точное потребление бросков, генерацию seed для реальных боёв, события, UI и баланс. Проверка реального iPhone Safari для этой технической библиотеки не выполнялась; нового пользовательского интерфейса нет.
