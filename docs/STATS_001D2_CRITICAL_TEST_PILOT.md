## [В РАЗРАБОТКЕ] Изолированная реализация

**Включение:** `CombatCore.createBattle(heroes, [], {rngSeed: 0, critChecks: true})`. При отсутствии `critChecks:true` генератор не бросает критов, даже если у тестового актёра есть поля. Сочетание `hitChecks:true, critChecks:true` поддерживается — сначала проверка попадания, только при попадании бросок крита. Действующие игровые миссии не передают ни `rngSeed`, ни `critChecks`, так что их поведение и баланс не меняются.

**Только для явно типизированных физ./маг. атак.** Legacy-атаки не получают критов даже при включённых флагах. Лечение, guard и положительные эффекты без урона не бросают крит. Из героев кампании никто не получил новых значений.

**Тестовая модель [ПРЕДЛОЖЕНИЕ]:**
- `critChance`: вероятность дополнительного броска от 0 до 100 **процентных пунктов**.
- `critDamage`: **полный процентный множитель базового урона**, в тесте допускается диапазон 100–1000% (×1–×10); 150% = ×1,5, не «+150%». Диапазон — **временная техническая граница**, не утверждённый игровой лимит.
- Оба поля **обязательны** только для атаки в специально крит-включённом тестовом бою; отсутствие/нечисловое значение ведёт к безопасному отказу до расхода хода и RNG. Это не означает, что реальные герои должны получать такие поля в v3.
- Порядок: `round(атака × множитель навыка)` → при крите `round(×critDamage/100)` → ослабление атакующего → соответствующая DEF → guard → Protection → HP. Проценты и правила округления пока служат лишь экспериментом, не каноном.

## События и воспроизводимость

- При срабатывании крита генерируется отдельное событие `critical` с `actorId`, `targetId`, `multiplierPercent` и номером броска `draw`, **до** существующего события `damage`. Журнал сообщает о критическом ударе, не меняя контракт `damage.amount`, `hpDamage`, `protectionDamage`. При отсутствии крита событие `critical` не отправляется.
- При включённом hitChecks: для каждой цели `hit` → если попали, `crit` → урон; при промахе нет события `critical`, нет второго броска и не расходуется guard / Protection. Для массового удара каждая живая цель проверяется отдельно в прежнем порядке бойцов; один крит **не усиливает всю группу**.
- Бросок крита потребляет один шаг генератора даже при `critChance=0` или `100`; это правило детерминированного интерфейса уже установлено Stats-001D0.
- Новые поля и запас будущих бросков проверяются **до** списания действия и до изменения событий: отсутствие полей, `NaN`, бесконечность, отрицательные шансы, шанс выше 100%, критический урон ниже 100% или выше 1000% отклоняют крит-включённое действие. RNG и кулдаун не меняются.
- Атакующие автоматические, ручные и вражеские действия уже идут через единый обработчик. Отдельный тест на автоматическую базовую типизированную атаку проверяет повторяемость по seed.

## Границы

- Формула `critChance`, пределы `critDamage` и реальный баланс **не утверждены**. Никакой видимый крит в основной кампании не включён.
- UI-анимация «КРИТ!» и настройка звука не добавляются; в изолированных VM-тестах проверяется форматирование нового события журналом.
- Не меняются уровни, классы, экипировка, 3 миссии, прогресс `v3`, энергия, награды, скорость, восстановление Safari и формулы физ./маг. обороны.
- В реальном браузере остаётся **`v0.3.53 · UIFIX001`**: нет пользовательских изменений, требующих мобильной приёмки на этом этапе.
- RNG используется только для тестовых seeded-битов. Перед настоящими критами нужны отдельные решение о происхождении seed, значениях героев и правилах повышения параметров. Технический LCG не криптографически защищён и не годится для честного защищённого PvP без серверного контроля.
