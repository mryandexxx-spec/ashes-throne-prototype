# Stats-001E2 — эффективность наложения негативных эффектов и сопротивление

**Дата:** 2026-11-08. **Статус: [В РАЗРАБОТКЕ] — тестовый opt-in пилот в отдельном PR.** Формула, числовые параметры и источники их развития не утверждены для кампании.

## Источники и границы

**[УТВЕРЖДЕНО]** В `game-design/progression/DECISIONS.md` приватного репозитория вселенной эффективность и сопротивление негативным эффектам входят в набор 14 характеристик; их формулы не утверждены. Пилот опирается на актуальный `main` игры после PR #120 (`9d318b3e1062a807624dd3d142cd251dc0fbab84`), `docs/Combat_Specification_1.0.md` и предыдущие исследования Stats-001D/E. Исследовательский PR #116 остаётся отдельным предложением.

## [ПРЕДЛОЖЕНИЕ] Тестовая модель

- Применяется только если бой создан с `CombatCore.createBattle(heroes, [], {rngSeed: 0, statusChecks:true})`.
- `statusChance = clamp(100 + debuffPotency - debuffResistance, 5, 100)`, где оба параметра выражены в процентных пунктах 0–100. Это **временная модель**, не согласованный баланс. Значения в тестах задаются явно, никакому игровому герою они не назначаются.
- Только **типизированные** физические или магические атакующие способности, содержащие действующий отрицательный эффект `weaken` (прямое `ability.weakening` либо `followUpEffects`), выполняют бросок сопротивления. Временный выбор: **уронная атака попадает → наносит урон → на выжившей цели отдельно проверяется эффект**. Чистые статусные умения без урона сейчас не реализуются и потребуют отдельного выбора автора.
- При сопротивлении отрицательный эффект не накладывается и не обновляет старые стеки. Урон/поглощение Protection остаются в силе, ход/перезарядка расходуются. Появляется событие `status-resisted`; событие успешного наложения `effect` отсутствует.
- Промах не вызывает проверку статуса. Погибшая цель не получает эффекта и не потребляет статусный бросок. Групповые атаки проверяют сопротивление отдельно для каждой **попавшей выжившей** цели в прежнем порядке.
- Положительные эффекты `guard`, лечение и дружественные ауры не сопротивляются. Для `followUpEffects.scope="primary"` статус проверяется только на исходной выбранной цели, если она попала и выжила. Для `scope="all"` — на каждой попавшей выжившей цели. Существующее правило `max(existing, incoming)` для повторного наложения не меняется.
- **Legacy-атаки не применяют новый механизм даже при `statusChecks:true`**. Без флага statusChecks все прежние ослабления гарантированы и никакие дополнительные броски не расходуются. Основная кампания не передаёт `rngSeed`/`statusChecks`, поэтому её результат остаётся прежним.
- Если отрицательная способность специально включена в statusChecks, атакующий должен иметь конечное `debuffPotency` в диапазоне 0..100, а **каждая целевая сущность** — конечное `debuffResistance` в 0..100. Нет автоматического присвоения отсутствующих полей. `NaN`, `Infinity`, строки, отрицательные, значения выше 100, неполный RNG приводят к отказу до первого события, списания хода, кулдауна и броска. Перед массовым действием резервируется верхняя граница количества статусных бросков, чтобы счётчик RNG не переполнился после частичной команды.

## Порядок обработки

`проверка законности всей команды → (hit?) → (critical?) → урон (weakening атакующего, penetration/DEF, guard, Protection, HP) → если цель выжила, сопротивление негативному эффекту → follow-up эффекты → завершение хода`.

Каждый исход статуса воспроизводим `BattleRng`; скорость анимации 1×/2×/4× и частота кадров не влияют на последовательность. Для нескольких отрицательных эффектов одной способности используются независимые статусные броски, а не один общий. Событие `status-resisted` не считается `effect` и не инициирует пассивные реакции успешного наложения.

## Изменения и тестирование

- `combat-core.js`: валидация `statusChecks`; отдельная проверка эффектов с RNG; общее правило для прямого `weaken` и отрицательных `followUpEffects`; отклонение некорректных полей.
- `combat-log.js`: нейтральное сообщение о сопротивлении.
- `tests/stats-001e2-debuff-resistance.test.js`: прямое наложение и сопротивление, групповые способности и primary/all follow-up, старые стеки, промах, смерть цели, отсутствие проверок без флага, legacy совместимость, валидация всей группы, комбинация hit+crit+status, повторяемость seed.
- Сохранение `progress.v3`, боевые награды, энергия, UI, экипировка, классы, скорость боя и версия интерфейса **не изменены**.

## Открытые авторские вопросы

1. Оставить ли модель `100 + potency − resistance` с минимальным 5% или рассмотреть иную базовую вероятность и верхние/нижние пределы?
2. Как решать отрицательные умения **без прямого урона**? Текущий эксперимент их не вводит.
3. Утверждение индивидуальных статов персонажей, зависимости от G/уровней/умений и источников seed для реальных боёв — отдельный этап после числовых испытаний.
4. До включения в сюжет необходимы балансовые прогоны, проверка повторов/наград/сохранений и пользовательская мобильная приёмка Safari.
