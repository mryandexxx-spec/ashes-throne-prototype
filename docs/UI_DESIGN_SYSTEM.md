# UI-SYSTEM-001 — единая художественная система интерфейса «Пепельного престола»

**Статус:** [УТВЕРЖДЕНО] направление и обязательность для новых экранов — решение владельца от 10.11.2026, основанное на принятой визуальной реализации HQ-UI-008 и ROSTER-UI-006. Конкретные новые компоненты и числовые параметры ниже — [ПРЕДЛОЖЕНИЕ], пока не приняты через соответствующие PR и мобильную приёмку.

**Область:** браузерная мобильная RPG, сначала iPhone Safari landscape, затем другие мобильные браузеры и desktop. **Это документ игрового репозитория, не канон мира.**

## 1. Источники и назначение

- GDD 3.0: мобильный landscape, понятная обратная связь, крупные области касания, отсутствие горизонтального overflow, производительность и общие компоненты.
- Текущий `main` (10.11.2026): принятая сцена штаба `#home` (HQ-UI-008) и визуальное направление коллекции `#collection` (ROSTER-UI-006, `v0.3.90`).
- Фактическая реализация: `index.html`, `styles.css`, `game.js`; художественные исходники `assets/hq-hall-painting-mobile.webp`, `assets/hq-hall-painting.webp`, `assets/hq-hall.svg`.
- Не считать стилевой слой ROSTER006 универсальной CSS-библиотекой: текущие селекторы локальны и не должны механически копироваться на каждую страницу.

**Правило:** вся новая работа по UI следует этой системе. Старые экраны переводить поэтапно, с отдельными PR. Нельзя ради визуальной унификации переписывать игровые правила или подключать 3D к обычным меню.

## 2. Художественные принципы — [УТВЕРЖДЕНО]

1. **Общий мир, а не веб-страницы.** Экран ощущается частью штаба, архива или иного уже утверждённого игрового пространства. Вне главного меню — знакомая атмосфера штаба с контрастным тёмным затемнением, а не пустая синяя подложка.
2. **Единая оболочка без «рамки в рамке».** Верхняя панель и навигация принадлежат общей системе; основной контент размещён на одном читаемом слое. Многократные вложенные полноразмерные рамки избегать.
3. **Материал и глубина.** Тёплая бронза, тёмный графит, дерево/металл только там, где они служат функции; объём создают локальный свет, тени, микрорельеф и портреты, а не шумный декор по всему экрану.
4. **Контент первичен.** Портреты, имена, статусы, действия и цель игрока важнее украшений. Читаемость выше прозрачности и художественного эффекта.
5. **Общая визуальная грамматика.** Согласованные типы HUD, заголовков, панелей, кнопок, полей, меток, прогресса, результатов, диалогов и карточек. Состояния различимы не только цветом.
6. **Нативный системный вид не должен случайно прорываться** в основной игровой UI (например, сортировка коллекции); при замене native-контрола обязательно сохранить клавиатуру, focus, Escape, подписи, касание и закрытие по нажатию снаружи.
7. **Функциональные исключения.** Боевая арена сохраняет собственную полноэкранную компоновку, HUD управления и приоритет производительности; её нельзя закрывать декоративной панелью только ради единообразия. Диалоги, ландшафтные ограничения и экран поворота тоже имеют специальную компоновку.

## 3. Предлагаемый набор дизайн-токенов — [ПРЕДЛОЖЕНИЕ]

*Значения — стартовые ориентиры из принятых CSS, не новая утверждённая палитра. Перед общим подключением проверить контраст и мобильные скриншоты.*

| Назначение | Кандидат |
|---|---|
| Фоновый графит | `#18181d`, `#241f22` |
| Темнее затемнённые слои | `#0c0d12`, `#151519` |
| Контуры бронзы | `#a78348`, `#bd925b` |
| Светлый металл | `#e0b978`, `#f0c879` |
| Основной текст | `#f4ebd8` |
| Вторичный текст | `#d9c5ab` |
| Особая информация/состояния | свои доступные контрастные цвета, не только золото |
| Радиусы | малые 5–8px; панели 10–14px |
| Касание | не менее 44×44px там, где возможно |
| Объём | один сильный источник света + локальные внутренние/падающие тени |

**Пока не вводить `--` токены массовой заменой по всему `styles.css`.** После пилота выбрать проверенные значения и добавить ограниченный слой `ui-system.css` либо начало существующего `styles.css` по решению техэтапа.

## 4. Библиотека интерфейсных паттернов — [ПРЕДЛОЖЕНИЕ]

| Паттерн | Обязательное поведение |
|---|---|
| **Scene shell** | Полноэкранная сцена/затемнение с safe-area, без дополнительной синей legacy-рамки |
| **HUD** | Компактные реальные данные игрока/ресурсов, не дублировать значения и не скрывать важные показатели |
| **Content panel** | Единая читаемая полупрозрачная панель в пространстве сцены; внутренние рамки только для разных смыслов |
| **Section heading** | Иерархия: контекст → название → короткое пояснение → доступный возврат |
| **Card** | Именованный объект, понятный статус и действие; нажатие 44px+, единая рамка/тень |
| **Button** | Primary / secondary / ghost / destructive + disabled, pressed, focus-visible |
| **Tag / badge** | Из данных игры; «★ Лидер» только для действующего лидера, тег «Сады над пропастью» у Рена — из HeroProfileData, не смешивать эти смыслы |
| **Filter / sort** | Указание активного состояния, доступная клавиатура и касание; сохранять выбор при возврате, где это предусмотрено |
| **Dialog** | Внутриигровая палитра, focus management, корректное закрытие и прокрутка при низком landscape |
| **Results / economy** | Иерархия результата, наград, доступного продолжения; никакой фиктивной валюты в заголовке |
| **Battle HUD** | Внятный активный герой, цели и возможности; высокая контрастность, низкая задержка, отсутствие фоновых анимаций вне боя |

## 5. Технические границы

- `#home` и `#collection` остаются эталонными **реализованными примерами**, но не переиспользуемыми компонентами один к одному.
- Общие стили вводить по мере миграции и только после проверки несовместимых экранов; стили пока локализовать с помощью классов/селекторов экрана.
- Не добавлять сборщик, фреймворк, тяжёлые шрифты, WebGL-сцены или зависимости ради стилизации.
- Использовать существующие арт-ресурсы по возможности; новый арт — отдельное утверждение и проверка веса/кэша.
- Избегать постоянной анимации, дорогостоящих `filter`, бесконечного `backdrop-filter`, неконтролируемых render loops и слушателей.
- CSS `:has()` уже используется для принятого ростера. Проверять поддерживаемую целевую версию Safari и fallback, если расширяем применение.
- Обеспечить `prefers-reduced-motion`, `focus-visible`, читаемые aria-label, `[hidden]`, scroll restoration, защиту от перекрытия `dialog` и от горизонтальной прокрутки.

## 6. Definition of Done для каждого нового UI-этапа

1. Перед изменением прочитаны `docs/UI_DESIGN_SYSTEM.md`, `docs/UI_MIGRATION_PLAN.md`, `docs/AI_WORKFLOW.md`, `docs/PROJECT_STATUS.md` и фактический `main`.
2. Задача определяет **сцену/смысл**, HUD, компоненты и исключения; не дублирует legacy UI.
3. Тексты, реальные данные, иерархия и доступность соответствуют утверждённой механике.
4. На мобильных landscape проверены 844×390 и 932×430 как минимум в доступном браузерном тесте, включая safe-area, отсутствие горизонтальной прокрутки, открытие меню/диалогов и возврат.
5. Добавлены регрессионные проверки ключевых переходов, кликов и состояний; Node/WebGL/landscape CI зелёные.
6. При изменении игры синхронизирована версия `package.json` / футер, подготовлен отдельный PR и перечень рисков.
7. После разрешённого merge владелец проверяет на реальном iPhone Safari: **первым шагом совпадение версии сборки**; автоматически пройденный тест не выдаётся за такую приёмку.

## 7. Что НЕ означает решение

- Никакого автоматического утверждения новых механик, рисунков, фракций или lore.
- Никакого разрешения слить будущие PR без владельца.
- Никакого утверждения, что уже существующие 17 экранов и 5 диалогов перешли на новый стиль.
- Никакой необходимости сделать каждую страницу одинаковой: единство языка, но адаптация к задаче экрана.
